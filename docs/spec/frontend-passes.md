## 0. Reading guide: the recursion-scheme vocabulary

Everything in the frontend is a fold over `Fix (Note n (ExpF e))`.

| Combinator | Definition | Traversal semantics |
|---|---|---|
| `cata alg` | `compiler/hs/lib/Language/Kanagawa/Recursion.hs:76-77` (`cata alg = para (const alg)`) | bottom-up; children already rewritten |
| `para alg` | `Recursion.hs:73-74` (`para alg t = alg t $ para alg <$> unfix t`) | bottom-up, **but** the algebra also receives the *original, un-rewritten* subtree as its first argument |
| `histo` | `Recursion.hs:68-71` | unused by the frontend passes |
| `desugar f` | `Desugar.hs:66-69` — `cata (\(Note n e) -> NotedExp n (f e))` | bottom-up rewrite that preserves the note |
| `desugar' f` | `Desugar.hs:71-74` | same, but the algebra also sees the note `n` |
| `desugarShallow f` | `Desugar.hs:76-79` — `para (\e' (Note n e) -> maybe e' (NotedExp n) (f e))` | **`Nothing` reverts the entire subtree to its pre-rewrite form.** This is the only "stop descending" mechanism in the codebase |
| `desugarShallow' f` | `Desugar.hs:81-84` | same, with the note |
| `desugarWithNote n f` | `Desugar.hs:91-94` — `para (\e' (Note n' e) -> NotedExp (n' <> n) (f e' e))` | rewrites *and* merges an extra note into every node (used to stack instantiation-site locations onto template bodies) |
| `parallel` | `Desugar.hs:54-55` — `parMap rpar` | per-file parallel map over the `[NotedExp]` program list |
| `parallelChunksOf k` | `Desugar.hs:57-61` | chunked parallel map |
| `mapWith`/`setWith`/`listWith`/`mapUniqueWith` | `Recursion.hs:87-111` | `para`-based collectors used by symbol/extern/error gathering |

**Composition direction.** All the passes are written as `desugar (f . g . h)`. Since `.` is ordinary
function composition applied to a single node's functor value, **`h` runs first, then `g`, then `f`, at
each node**, and the whole thing runs bottom-up. Reading a pass left-to-right gives you the *reverse*
of the per-node rewrite order.

**The AST.** `ExpF e a` is the single 93-constructor functor (`Parser/Syntax.hs:282-584`; the complete
constructor list, in declaration order — which is also the derived `Ord` order — is
`SeqF FlagAttrF IntAttrF AttrF FunctionModifierF AutoF VoidF BooleanF FloatF StringF IntegerF ParamIntF
UnsignedF ParamUintF ConstF ReferenceF ArrayF TemplateInstanceF TemplateParamF TypeParamF TypenameF
FunctionTypeParamF FunctionTypeF ThisF DesignatorF PositionalF InitializerListF BitOffsetF ByteOffsetF
IntLiteralF FloatLiteralF BoolLiteralF StringLiteralF InterpolatedStringF IdentifierF ScopedNameF
QualifiedIdentifierF TypeIdentifierF FunctionSpecifierF EnumValueF NamedValueF BinaryF UnaryF
FunctionCallF ArrayAccessF ArrayAccessLValueF MemberAccessF CastF MuxF ConcatF FanOutF StaticF
AnnotatedF BarrierF ReorderF ReturnF DoWhileF UnrolledForF StaticForF RangeForF IfF StaticIfF SwitchF
SwitchCaseF SwitchDefaultF AssignF NestedScopeF ModuleIdentifierF ModuleDiffF ModuleDeclF
EnumConstantF EnumF StructF UnionF ClassF DefaultInitializationF PrivateF PublicF TemplateF DecltypeF
AliasF CaptureF VariableF FuncParamF FunctionF FunctionDeclF LambdaF ExportTypeF ExternF
StaticAssertF StaticAssertLegacyF WarningF ErrorF`).
`Note x f a` (`Parser/Syntax.hs:586-591`) attaches an annotation. `NotedExp n e = Fix (Note n (ExpF e))`
(`Parser/Syntax.hs:630-632`). Two pattern-synonym families are generated by Template Haskell:
`Language.Kanagawa.Parser.Syntax.Pattern` matches one level (`Note _ (XxxF …)`,
`Parser/Syntax/Pattern.hs:16`) and `…Syntax.FixPattern` matches through the `Fix`

that imports the non-`Fix` family (`Mangle.hs:13`) because its `mangle` is a `cata` algebra.

## 1. Entry points

```haskell
-- compiler/hs/app/Main.hs:76
let desugared = foldr1 append $ frontend passes template_passes template_iterations exprs
```

`exprs` is one `NotedExp Src (ParseError …)` **per parsed file** (`Main.hs:70-72`); the whole frontend
operates on that *list*, and the files are concatenated into a single `SeqF` only afterwards
(`Main.hs:76`, `Main.hs:104-105`).

```haskell
-- compiler/hs/lib/Language/Kanagawa/Frontend.hs:34-35
frontend :: (Semigroup n, Ord (Token s), Ord s, Ord e, Eq n) => Int -> Int -> Int -> [NotedExp n (ParseError s e)] -> [NotedExp (Typed n) (ParseError s e)]
frontend frontendPasses templatePasses templateIterations = desugarPasses frontendPasses templatePasses templateIterations . map noteType
```

`noteType` (`Type.hs:973-976`) wraps every note as `Typed TUnresolved n`; `Typed`
(`Type.hs:445-450`) is `{ typeof :: !Type, untype :: a }`. So the note carried by every node from here
on is *(inferred type, source span)*.

After the frontend, `Main.hs:81` collects `nub $ errors $ unnoteType desugared`; a non-empty list
aborts before codegen (`Main.hs:82-84`).

The `Eq n` constraint on `frontend`/`desugarPasses` (`Frontend.hs:34,37`) is not used by any callee I
could find — **UNVERIFIED**, likely vestigial.

## 3. The actual execution order (derivation)

`foldr f z [a,b,c] = f a (f b (f c z))`. With `f = ($)`:

```
foldr ($) z [p1,p2,…,p19]
  = p1 $ (p2 $ (… $ (p19 $ z)))
  = p1 (p2 (… (p19 z)))
```

`p19` is applied to the seed `(program, False)` first; `p1` is applied last. **The last entry in the
written list executes first.** (`Frontend.hs:38`.)

Two independent confirmations from the source itself:

1. `interpolatedStringPre` is at list position 19 (`Frontend.hs:76`) and `interpolatedStringPost` at
   position 2 (`Frontend.hs:57`). "Pre" must run before "Post"; only the reversed order gives that.
2. `instantiateTemplates` is at position 12 (`Frontend.hs:67`) and `removeTemplate` — which deletes
   `TemplateF` nodes and their leftovers — is at position 5 (`Frontend.hs:60`). Templates must be
   instantiated before their definitions are deleted; only the reversed order gives that.

### Driver combinators

* `pass fn (p, hasErrors)` — `Frontend.hs:42-44`. If the flag is set, the pass is a no-op; otherwise
  `fn` is applied to the whole file list. The flag is never *set* here.
* `passPar = pass . parallel` — `Frontend.hs:46`. Same, but `fn` maps over files in parallel.
* `checkPar fn (p, hasErrors)` — `Frontend.hs:48-52`. Maps in parallel, then **sets** the flag to
  `hasErrorSymbol (getSymbols p')`, i.e. "does the rewritten program contain any `ErrorF` node?"
  (`Symbols.hs:34-35`, keyed under `["$errors"]` per `Symbols.hs:31-32,67`).
* `withSymbols fn p = fn (getSymbols $ fst p) p` — `Frontend.hs:40`. Recomputes the **whole-program**
  symbol table from the current program state, lazily.

Only three of the nineteen passes can set the error flag: #1 (`checkPar`, `Frontend.hs:48-52`),
#8 (`instantiateTemplates`, `Template.hs:56`) and #9 (`undefinedSymbols`, `Frontend.hs:87`). Every
other pass merely propagates it. So a type error produced by, say, `validateProgram` (#19, the last
pass) never suppresses anything — it just lands in the final `errors` collection in `Main.hs:81`.

## 4. Pass-by-pass specification

Notation: *eliminates* = node kinds that cannot survive the pass; *introduces* = node kinds the pass
can create.

### Pass 1 — early syntactic normalization + validation (`Frontend.hs:74-79`)

Five algebras fused into one bottom-up `desugar`; per node they run **right to left**:

1. **`redundantNameScope symbols`** — `Frontend.hs:160-167`.
   Consumes `QualifiedIdentifierF (ScopedNameF a (Just _) c)`. If looking up the *unqualified*
   `ScopedNameF a Nothing c` in the whole-program symbol map yields a symbol with the same qualifier,
   the explicit qualifier is dropped. Produces `QualifiedIdentifierF` with `ScopedNameF … Nothing …`.
   Eliminates: redundant `Just` qualifiers. Introduces: nothing.
   Also exported standalone as `removeRedundantNameScope` (`Frontend.hs:157-158`) and used by
   `--pretty-print` mode (`Main.hs:52`).
2. **`localMemberFunctions`** — `Frontend.hs:219-225`. For a `FunctionF` whose `funcKind ==
   MemberFunction`, rewrites *every* nested `FunctionF` in its body to `funcKind = MemberFunction`
   (a nested full `desugar` — quadratic in nesting depth). No node kinds change.
3. **`freeNonInlineFunctions`** — `Frontend.hs:227-231`. `FunctionF _ FreeFunction _ modifier …`
   without `Just (FunctionModifier Inline)` → `ErrorF "Free functions must be declared \`inline\`"`.
   Eliminates: non-inline free `FunctionF`. Introduces: `ErrorF`.
4. **`interpolatedStringPre`** — `Frontend.hs:233-239`.
   `InterpolatedStringF [(s, Nothing)]` (a single literal segment) → `StringLiteralF s`.
   Otherwise each segment `(s, Just (a, True, b, f))` becomes `(s ++ showPretty a ++ " = ", Just (a,
   False, b, f))` — i.e. the `{x=}` "echo the expression text" form is expanded here.
   Eliminates: literal-only `InterpolatedStringF`, the `True` flag. Introduces: `StringLiteralF`.
5. **`validateTypedLiterals`** — `Frontend.hs:210-217`. `IntLiteralF (Just t) x` → `ErrorF` if
   `literalWidth t == 0`, or if `x /= truncateInt/truncateUInt w x` (`Internal.hs:34-41`).
   Introduces: `ErrorF`.

Order dependence: must precede everything (it is the only place `{x=}` interpolation and free-function
inline-ness are checked before types exist), and `checkPar` here is the gate that stops the rest of the
pipeline on syntax-level errors.

### Pass 2 — `higherOrderFunctions` (`Function.hs:313-363`)

Driver: `withSymbols $ passPar . desugar' . higherOrderFunctions` (`Frontend.hs:73`).

Consumes: `FunctionF` whose parameter list, after alias resolution (`resolvedFuncParams`,
`Function.hs:134-143`), contains any `FuncParamF` with `paramType` a `FunctionTypeF`.
Produces: a `TemplateF` wrapping the rewritten function.

For each function-typed parameter at index `i` two template parameters are emitted
(`Function.hs:327-348`):

* `TemplateParamF declScopeName Typename (name <> "$capture") (i*2) Nothing` — the capture type;
* `TemplateParamF declScopeName (closureFunctionType …) name (i*2+1) Nothing` — the lowered function
  type, which is the original `FunctionTypeF` with an extra leading parameter of the capture type
  (`Function.hs:334-340`).

The parameter itself is retyped to
`Closure< closureFunctionType, closureFunctionTypeParam, captureTypeParam >`
via `closureInstance` (`Function.hs:180-184`, `Function.hs:353-359`), i.e. a `TypeIdentifierF`
containing a `TemplateInstanceF` of `data'closure'core'Closure` (`Type.hs:121-122` =
`["@data@closure@core", "Closure"]`).

If the function is not `inline`: `desugarError "Non-inline higher order functions are not supported"`
(`Function.hs:325`).

Second clause (`Function.hs:361`): `TemplateF p1 (Template p2 e)` → `mergeTemplateParams p1 p2 e`
(`Function.hs:264-281`), flattening the nested template created when an *already* templated function
also takes function-typed parameters, and re-indexing `p2`'s `TemplateParamF`/`TypeParamF` indices by
`+ length p1`.

Eliminates: function-typed `FuncParamF` (for inline functions). Introduces: `TemplateF`,
`TemplateParamF`, `TemplateInstanceF`, `TypeIdentifierF`, `FunctionTypeParamF`, `ErrorF`.

Order dependence: must run before template instantiation (#8) since it *creates* templates; must run
before `inferType` (#6) so the closure types exist when types are computed.

### Pass 3 — `reifyEnums` then `captureThis` (`Frontend.hs:72`)

* **`reifyEnums`** — `Frontend.hs:195-208`. In an `EnumF` body (a `SeqF` of `EnumConstantF`), every
  constant without an explicit `constValue` gets `IntLiteralF Nothing 0` for the first one and
  `BinaryF Add <previous value> (IntLiteralF Nothing 1)` afterwards. Note the value is an *expression*,
  not a folded number; constant folding happens later in `evaluateConstexpr`.
  Introduces: `IntLiteralF`, `BinaryF`. Eliminates: `EnumConstantF` with `constValue = Nothing`.
* **`captureThis`** — `Frontend.hs:185-193`. For a `ClassF`, `desugarShallow captureThis'` over its
  body prepends `ThisF declScopeName` to `lambdaCaptures` of every `LambdaF`; `captureThis' ClassF{} =
  Nothing` stops at nested classes — and because of `desugarShallow`'s revert semantics
  (`Desugar.hs:76-79`), a nested class's subtree is restored to its *pre-rewrite* form entirely.
  Introduces: `ThisF` inside `lambdaCaptures`.

Order dependence: `captureThis` must precede `desugarLambdas` (which runs inside pass #8,
`Template.hs:78`) so that `this` is part of the capture tuple.

### Pass 4 — `deduceTemplateArgs` (`Type.hs:1385-1593`)

Driver: `withSymbols $ passPar . deduceTemplateArgs` (`Frontend.hs:71`). A `desugar'` (note-aware).

Rewrites (`Type.hs:1390-1404`):
* `MemberAccessF a b` with undefined node type and `a` of class type →
  `FunctionSpecifierF (Just a) (qualifiedIdentifier [] (classQName ++ [name b]) b)`.
* `FunctionSpecifierF (Just a) b` whose `b` is qualified by `$unresolved` and `a` is a class →
  requalify `b` with the class's qualified name.
* `DesignatorF a (FunctionSpecifier x y)` → deduce `y` with no argument types.
* `FunctionCallF a (FunctionSpecifier x y) c` → deduce `y` from the call's argument types.
* `NamedValueF a@QualifiedIdentifier{}` with unresolved type → deduce.
* `TypeIdentifierF s t@TemplateInstance{}` and `ScopedNameF s (Just t@TemplateInstance{}) a` → deduce.

Deduction (`Type.hs:1434-1508`) fills a partially-specified `TemplateInstanceF` argument `SeqF` from
(a) explicit arguments, (b) unification against the function signature, (c) `TemplateParamF` default
arguments substituted through `resolveTypeParam` (`Type.hs:1422-1428`). The unification runs in a
`ReaderT DeduceType (State (Map Int (Maybe (DeduceType, TArg))))`: parameters are matched against
argument types, then template parameters against explicit arguments, then the return type
(`Type.hs:1476-1480`). Conflicts are reconciled by `setArg`/`reconcile` (`Type.hs:1482-1508`) with the
complete rule set: an existing `TInitializer` binding always loses; a `Nothing` always loses; two
`DeduceSupertype` integer/enum bindings join to `tSuper`; otherwise the subtype/supertype relation
`<:` picks the winner according to the current `DeduceType` (`DeduceSupertype | DeduceSubtype`,
`Type.hs:1382-1383`); unresolved and `TError` bindings win over resolved ones; and an irreconcilable
pair becomes `TError "Conflicting template argument deduction results for parameter \`P\`. Could be
\`X\` or \`Y\`."`.

Eliminates: `MemberAccessF` on class objects (becomes `FunctionSpecifierF`), short argument lists.
Introduces: `FunctionSpecifierF`, `QualifiedIdentifierF`, `TemplateInstanceF`, `IntLiteralF`, `ErrorF`.

### Pass 5 — `intrinsics` (`Type.hs:1069-1084`)

A pure `cata` that assigns a `TFunction` type to `QualifiedIdentifierF`/`ScopedNameF` nodes whose
qualified name is exactly one of — this is the complete list —
`["__print"]`, `["assert"]`, `["__cycles"]`, `["__str_cnt"]`, `["__assert_str_eq"]`
(`Type.hs:1079-1083`). Uses `resolveTypeOf` (`Type.hs:1037-1048`) so it only fills in undefined types.
No structural change.

### Pass 6 — `inferType` (`Type/Inference.hs:27-45`)

Whole-program, iterated to a fixpoint:

```haskell
-- compiler/hs/lib/Language/Kanagawa/Type/Inference.hs:30-45
inferType = loop []
  where
    loop prevSig p
        | prevSig == sig = inferred
        | otherwise      = loop sig inferred
      where
        symbols = getSymbols' TemplateDecl p
        inferred = parallel (inferExpTree symbols) p
        -- Count of unresolved types is monotonically decreasing
        sig :: [Integer]
        sig = parallel (para go) inferred
```

* Termination measure: one `Integer` per file = the count of nodes whose type is not `tResolved`
  (`Type/Inference.hs:41-45`). The loop stops when the vector is unchanged between iterations, **not**
  when it reaches zero.
* Symbol table config is `TemplateDecl` (`Symbols.hs:28,46-47`): template *declarations* are inserted
  but their bodies contribute no symbols.
* Per-node algebra (`Type/Inference.hs:50`):
  `staticControl . unfix . evaluateConstexpr symbols . unfix . inferExpType symbols` — infer, then
  constant-fold, then elaborate static control flow, bottom-up.
* Descent is deliberately incomplete (`Type/Inference.hs:52-68`), and this is load-bearing:
  * `LambdaF` — children are **not** visited at all;
  * `FunctionF` with any function-typed parameter — children not visited;
  * `FunctionF` with unresolved parameters — only `funcParams` visited;
  * `FunctionF` in a local scope (`isLocalScope`, `Desugar.hs:176-180`: last scope component starts
    with `$`) — only `funcParams` and `funcReturnType` visited;
  * `TemplateF` — only `templateParams` visited, never `templateDecl`;
  * `StaticIfF` — only the condition visited;
  * local `ClassF` — children get `staticControl` only (no type inference);
  * everything else — all children.

  Because branches of a resolved `static if` are only reachable *after* the `StaticIfF` node is
  replaced, the outer fixpoint loop is what eventually types them.

Eliminates: `StaticIfF`, `StaticForF`, `DecltypeF`, `ParamIntF`, `ParamUintF`, `BitOffsetF`,
`ByteOffsetF`, `UnaryF Clog2/BitSizeof/ByteSizeof`, foldable `BinaryF`/`UnaryF`/`CastF`/`MuxF`/`StaticF`
(see §8). Introduces: `IntLiteralF`, `BoolLiteralF`, `FloatLiteralF`, `EnumValueF`, `IntegerF`,
`UnsignedF`, `UnrolledForF`, `NestedScopeF`, `SeqF`, `ErrorF`, plus type annotations on every node.

### Pass 7 — `trimExternClasses` (`Frontend.hs:315-335`)

Whole-program: `externClasses` is the set of qualified names of all `Extern` declarations across all
files (`Frontend.hs:331-335`). For each `ClassF` in that set, `desugarShallow trim` over its body
replaces every member `FunctionF` body with `SeqF [ReturnF value]` where `value` is `Nothing` for
`Void` return type and `Just (InitializerListF (SeqF []))` otherwise (`Frontend.hs:321-326`).
`trim ClassF{} = Nothing` stops (and reverts) at nested classes.

Eliminates: bodies of extern-class methods. Introduces: `ReturnF`, `InitializerListF`, `SeqF`.

### Pass 8 — `instantiateTemplates` (`Template.hs:46-164`)

### Pass 9 — `undefinedSymbols` (`Frontend.hs:82-155`)

A `para` (needs the original node to read its pre-rewrite name). Complete clause list
(`Frontend.hs:91-109`):

* abbreviated templates are skipped entirely (`Frontend.hs:91-92`);
* `TemplateF` — the *body* is taken from the rewritten tree but only the *parameters'* error flags
  propagate (`Frontend.hs:93-94`);
* `TemplateInstanceF` — only the argument list's error flag propagates (`Frontend.hs:95-96`);
* `TypeIdentifierF` / `ScopedNameF` with `tIsUndefined` type and no existing errors → `ErrorF "Type
  name not in scope: …"` (`Frontend.hs:97-100`);
* `QualifiedIdentifierF` with `tIsUndefined` type → `ErrorF "Symbol name not in scope: …"`
  (`Frontend.hs:101-102`);
* `MemberAccessF a b` with undefined type but resolved object type → the *member* is replaced with
  `ErrorF "Undefined member \`x\` of type \`T\`"` (`Frontend.hs:103-106`);
* `FunctionSpecifierF (Just a) _` where `a`'s type is unresolved → returns the original node, no error
  (`Frontend.hs:107-108`).

Hints (`Frontend.hs:115-153`) use `restrictedDamerauLevenshteinDistance` over the whole-program symbol
map: at most 3 suggestions, sorted by distance, accepted when `distance <= 1 && moduleDefined name` or
`distance <= min 3 (length name `div` 2) && inScope name`.

Returns `(p', or errs)` — **sets the error flag**.

### Pass 10 — `cata typeErrors` (`Frontend.hs:169-174`)

Any node whose `typeOf` satisfies `tIsError` and which contains no `ErrorF` descendants is replaced by
`errorMsg (showPretty $ typeOf e)`. Converts type-level `TError` payloads into AST-level diagnostics.
Introduces: `ErrorF`.

### Pass 11 — `unresolvedFunctionTemplateArgs` (`Frontend.hs:434-444`)

`para`. For `FunctionCallF a (FunctionSpecifier _ (QualifiedIdentifier TemplateInstance{})) c`, every
argument in `c` whose type is not resolved becomes `ErrorF "Unresolved argument"`. `Template{}`
subtrees are returned untouched (`Frontend.hs:439`). Introduces: `ErrorF`.

### Pass 12 — `unresolvedTemplates` (`Frontend.hs:409-432`)

`para`. For `QualifiedIdentifierF`/`TypeIdentifierF` wrapping a surviving `TemplateInstance`
(i.e. one instantiation failed to happen), emits one of:

* the instance's own `diagnostics` plus, comparing `length args` to `length params`
  (`Frontend.hs:420-423`): `LT` → `"Could not deduce all arguments for template \`X\`"`;
  `GT` → `"Too many arguments specified for template \`X\`"`; `EQ` → per-argument
  `"Unresolved argument for the parameter P of template X"` for each `a` with
  `not (templateArgResolved a)` and `a` not already an `Error`;
* if that list is empty → `"Failed to instantiate template"`;
* if the template symbol is missing → `"Undefined template \`X\`"` (`Frontend.hs:432`).

The definition-site note is merged into the error note via `errorMsgWithContext`
(`Frontend.hs:419`, `Error.hs:150-151`). `Template{}` subtrees are skipped (`Frontend.hs:414`).

### Pass 13 — `validateExportableClasses` (`Frontend.hs:337-391`)

Whole-program list pass. Builds `exportableClasses :: Map QualifiedName note` from every `ExportType`
and `Extern` declaration, transitively including the classes of *public object members* of those
classes (`Frontend.hs:351-366`). Then, for each `ClassF` in the map, `mapClassMembers`
(`Desugar.hs:115-121`, tracking `Public`/`Private` state) rejects:

* public `Variable` of function type → `"Public callback is not allowed in an exportable class"`;
* any other public `Variable` → `"Public field …"`;
* public `Function` with `Inline` modifier → `"Public inline method …"`;
* public function with any attribute outside the allow-list → `"Public method with [[A]] attribute …"`.

Complete attribute allow-list (`Frontend.hs:378-386`): `TFlagAttr Async`, `TFlagAttr NoBackPressure`,
`TFlagAttr Pure`, `TFlagAttr Reset`, `TIntAttr Latency _`, `TIntAttr MaxThreads _`,
`TIntAttr ThreadRate _`. Everything else is rejected.

Also: `ExportTypeF _ a` where `a`'s type `tIsTemplate` → `"Type template cannot be exported. Perhaps
you meant to export an instance of the template?"` (`Frontend.hs:340-341`).

### Pass 14 — `validateExtern` (`Frontend.hs:304-313`)

`ExternF a b` where `b` does not resolve to `Class{}` or `Template _ Class{}` → `ErrorF "Invalid extern
declaration. Only classes and class templates can be declared as external."`.

### Pass 15 — `desugar removeTemplate` (`Frontend.hs:298-302`)

```haskell
removeTemplate TemplateF{..} = SeqF $ diagnostics templateDecl ++ concatMap diagnostics templateParams
removeTemplate x
    | isAbbreviatedTemplate x = SeqF []
    | otherwise = removeNestedSeq x
```

Eliminates: **all** `TemplateF` nodes (replaced by a `SeqF` of only the diagnostics they contained) and
all abbreviated-template functions (`FunctionF`/`FunctionDeclF` with any `auto` parameter,
`Parser/Syntax.hs:722-724`) — those are deleted outright, since pass 8 already emitted a real template
for them. Also flattens nested `SeqF` (`Desugar.hs:132-137`).

Order dependence: strictly after #8; strictly before #16-#19 which assume no templates remain.

### Pass 16 — `postDesugar` (`Frontend.hs:176-183`)

One `desugar` of five algebras; per node they run **right to left**:

1. **`thisReference symbols`** (`Frontend.hs:453-457`) — `ThisF n` is replaced by
   `NamedValueF (localIdentifier n varName)` if a `Variable` named `$this` is in scope. This is how a
   lambda body's `this` becomes a reference to the captured copy.
2. **`returnVoid`** (`Frontend.hs:293-296`) — `ReturnF (Just e)` where `e` has void type becomes
   `SeqF [e, ReturnF Nothing]`, i.e. `return f();` → `f(); return;`.
3. **`unresolved`** (`Frontend.hs:400-407`) — the complete list of "should have been folded by now"
   diagnostics:
   * `ByteOffsetF t f` and `BitOffsetF t f` → `offsetErr` (`Frontend.hs:446-449`): if `t` is a struct,
     `"Undefined field"` on `f`; otherwise `"Field offset is only defined for structs"` on `t`;
   * `UnaryF Clog2 _` → `"clog2 argument did not evaluate to a positive integer constant"`;
   * `ParamIntF{}` → `"int width did not evaluate to a positive integer constant"`;
   * `ParamUintF{}` → `"uint width did not evaluate to a positive integer constant"`;
   * `StaticIfF{}` → `"static if predicate did not evaluate to a boolean constant"`.
   (`StaticForF` is **not** in this list — an unresolved `static for` survives as `UnrolledForF` or as
   itself; see §8.)
4. **`staticAssert`** (`Frontend.hs:393-398`) — `StaticAssertF (BoolLiteral True)` → `SeqF []`;
   `BoolLiteral False` → `"static assertion failed"`; anything else → `StaticAssertF` wrapping
   `"static assertion expression did not evaluate to a boolean constant"`.
5. **`resolveNames symbols`** (`Frontend.hs:273-286`) — `QualifiedIdentifierF a` resolving to a
   `Function`, `EnumConstant` or global `Variable` gets fully qualified (`makeQualified`,
   `Desugar.hs:190-191`); if its qualifier is already a prefix of its scope it is made *un*qualified
   (`makeUnqualified`, `Frontend.hs:288-291`). `FunctionSpecifierF (Just a) b` makes `b` unqualified;
   `FunctionSpecifierF Nothing (NamedValue b)` unwraps the `NamedValueF`.

### Pass 17 — `deduceAuto` (`Type.hs:1595-1610`)

`desugar'`. `FunctionF` with `isAuto funcReturnType` → replaces it with an expression built from the
inferred `tReturn` of the node's type, or `ErrorF "Could not deduce function return type"`.
`VariableF` with `isAuto varType || isConstAuto varType` → likewise, or `"Could not deduce variable
type"`. The replacement expression is produced by `expFromType` (`Type.hs:1612-1660`), whose complete
mapping from `Type` to `ExpF` is listed there; `TTemplate`, `TInitializer`, `TDesignator`,
`TPositional`, `TArray _ _ []`, `TError`, `TUndefined`, `TUnresolved`, `TUntyped` all map to `Nothing`

Eliminates: `AutoF` in declaration positions. Introduces: `VoidF`, `BooleanF`, `FloatF`, `StringF`,
`IntegerF`, `UnsignedF`, `ConstF`, `ReferenceF`, `ArrayF`, `FunctionTypeF`, `TypeIdentifierF`,
`ScopedNameF`, `SeqF`, `IntLiteralF`, `AttrF`, `IntAttrF`, `FlagAttrF`, `ErrorF`.

### Pass 18 — `desugar interpolatedStringPost` (`Frontend.hs:241-271`)

For each interpolation segment `(s, Just (a, b, c, f))`:
* `validateFormat` — with no format spec, `a` must be a value type, else
  `"The type of interpolation expression \`T\` is not a value type"`; with a spec, `a` must be int,
  enum or float, or bool with `Bin`, else `"Invalid format specifier \`X\` for the value of type
  \`T\`"`;
* `validateAlignment` — the alignment expression must have folded to an int literal, else
  `"Interpolated string alignment did not evaluate to an integer constant"`;
* `updatePrecision` — when `formatPrecision` is `Nothing`, it is filled from `sizeOf a` as
  `Bin → n`, `Oct → (n+2) div 3`, `Dec → Nothing`, `Hex → (n+3) div 4`, `HexUpper → (n+3) div 4`
  (`Frontend.hs:250-255`). Complete list of `FormatSpecifier`: `Bin|Oct|Dec|Hex|HexUpper`
  (`Parser/Syntax.hs:233-246`, shown as `b|o|d|x|X`).

### Pass 19 — `validateProgram` (`TypeCheck.hs:33-216`)

`desugar'` with the node's note available. Complete top-level clause list (`TypeCheck.hs:38-58`):
`UnaryF BitSizeof`/`ByteSizeof` pass through; other `UnaryF`, `BinaryF`, `FanOutF`, `MuxF`,
`ParamIntF`, `ParamUintF` → `checkInvalidType`; `FunctionCallF` → argument arity/conversion checks
(`TypeCheck.hs:87-97`, first argument skipped for `[[pipelined]]`); `ArrayF` → `checkArraySize`;
`IntAttrF` → `errorIfNotInteger`; `EnumF` → base-type and per-constant range checks

## 5. `--frontend-passes=N`

```haskell
-- compiler/hs/lib/Language/Kanagawa/Frontend.hs:38
desugarPasses frontendPasses templatePasses templateIterations program = fst $ foldr ($) (program, False) $ drop (length passes - frontendPasses) passes
```

`drop k` removes from the **front** of the written list. Since the *last* written entry executes
*first*, dropping from the front removes the *latest-executing* passes. So:

> `--frontend-passes=N` runs exactly the first `N` passes in execution order (execution-order table
> in §3), and stops.

CLI plumbing: `passes` field with `&= name "frontend-passes" &= explicit &= opt (maxBound::Int)`,
default `maxBound::Int` (`compiler/hs/app/Options/CmdArgs.hs:104`, field at
`compiler/hs/app/Options.hs:94`); forwarded as the first argument of `frontend`
(`compiler/hs/app/Main.hs:76`).

`length passes = 19`.

| N | `drop (19 - N) passes` | Effect |
|---|---|---|
| **0** | `drop 19 passes = []` | `foldr ($) (program, False) [] = (program, False)`; the returned program is exactly `map noteType exprs` — the raw parse tree with every node typed `TUnresolved`. No desugaring at all; `Main.hs` will hand that to codegen if there are no parse errors. |
| **1** | `drop 18 passes = [passes !! 18]` = the `Frontend.hs:74-79` entry | Only execution-order pass #1 runs (`redundantNameScope` … `validateTypedLiterals`), and because it is driven by `checkPar` the returned error flag is meaningful. |
| **20** | `drop (19 - 20) = drop (-1) passes = passes` | Haskell's `drop` returns the whole list for `n <= 0`, so N ≥ 19 is identical to the default. |

The default `maxBound::Int` gives `19 - 9223372036854775807 = -9223372036854775788` (no overflow —
still ≥ `minBound`), hence `drop` of a negative number, hence all passes.

**Bisection recipe**: compile with `--frontend-passes=0,1,2,…` and diff `--dump-program` /
`--dump-types` output (`Main.hs:78-80`, `Main.hs:88-91`) to find the first pass that introduces a
regression.

## 6. Template instantiation: the fixpoint

`compiler/hs/lib/Language/Kanagawa/Template.hs:46-164`. Header comment at `Template.hs:29-44` states
the intent: replace `TemplateF` with a `SeqF` of instances, replace `TemplateInstanceF` with a
decorated name, match arguments to parameters *by index and declaration scope*, and recurse because
templates nest.

### 6.1 The loop

```haskell
-- Template.hs:53-58
instantiateTemplates templatePasses templateIterations (program, hasErrors)
    | hasErrors = (program, hasErrors)
    | hasErrors' = (program', hasErrors')
    | templateIterations == 0 || Map.null decidedInstances = (parallel (desugar deduplicateInstances) program', False)
    | otherwise = instantiateTemplates templatePasses (templateIterations - 1) (inferType $ parallel (desugar (instantiate . resolve)) program', False)
```

with

```haskell
-- Template.hs:60-63
    program' = foldr ($) program passes'

    passes'
        | templateIterations == 0 = drop (length passes - templatePasses) passes
        | otherwise               = passes
```

**Termination conditions**, in the order tested:
1. incoming error flag → return unchanged;
2. `hasErrorSymbol (getSymbols program')` — any `ErrorF` anywhere → return `(program', True)`
   (`Template.hs:83-84`);
3. `templateIterations == 0` — the iteration budget is exhausted;
4. `Map.null decidedInstances` — nothing left that *can* be instantiated. **This is the only natural
   termination condition** (the default budget is `maxBound::Int`).

There is no occurs check, no depth limit, and no per-template instantiation cap: a template whose
instantiation produces a new distinct instance of itself will iterate until `maxBound` iterations.

Each iteration ends with `inferType` over the rewritten program (`Template.hs:58`), so types are
recomputed for the freshly minted instances before the next round decides what else is instantiable.

### 6.2 The inner 9-pass sub-pipeline (also reversed)

```haskell
-- Template.hs:70-81
    -- desugaring passes before template instantiation
    passes = [ withSymbols $ parallel . templateTypeCheck
             ,               inferType
             , withSymbols $ parallel . deduceTemplateArgs
             ,               parallel $ desugar closureCalls
             ,               inferType
             ,               parallel $ moveFunctions
             ,               parallel $ desugarShallow' abbreviatedFunctionTemplate
             ,               parallel $ desugarLambdas
             , withSymbols' NoTemplate $
                             parallel . desugar . addLambdaWrappers

```

`program' = foldr ($) program passes'` (`Template.hs:60`) — same `foldr ($)` idiom, so **again the
last entry runs first**. Execution order, per iteration of the outer loop:

| # | Line | Pass | Notes |
|---|---|---|---|
| T1 | `Template.hs:79-80` | `addLambdaWrappers` | symbols computed with `NoTemplate` config (`Symbols.hs:57-59`: a `Template`'s own decl symbol is dropped from the map) |
| T2 | `Template.hs:78` | `desugarLambdas` | |
| T3 | `Template.hs:77` | `desugarShallow' abbreviatedFunctionTemplate` | |
| T4 | `Template.hs:76` | `moveFunctions` | function/class hoisting |
| T5 | `Template.hs:75` | `inferType` | whole-program fixpoint |
| T6 | `Template.hs:74` | `desugar closureCalls` | needs T5's types (`tIsClosure`) |

CLI: `--template-iterations` / `--template-passes`, both defaulting to `maxBound::Int`

### 6.3 What counts as a "decided" instance (the memo key)

```haskell
-- Template.hs:86-108
    decidedInstances = Map.unionsWith Map.union $ parallelChunksOf 4 (Map.unionsWith Map.union) $ parallel (para decided) program'
      where
        decided e@(TemplateInstance a b@(Seq args)) x
            | all Map.null x && templateResolved symbols template b =
                Map.singleton templateQualifiedName directInstance
            | templateArgsResolved template args =
                Map.unionsWith Map.union $ Map.unionsWith Map.union x : indirectInstances template
          where
            directInstance = Map.singleton b $ note $ unfix e
            indirectInstances (Just t@(Template params _)) =
                map (para decided . resolveTemplateParam symbols t args) params
            indirectInstances _ = mempty
            template = lookupSymbol a symbols
            templateQualifiedName = getQualifiedName $ fromJust template

        decided _ (Note _ StaticIfF{..})  = staticIfCond
        decided _ (Note _ StaticForF{..}) = forLimit
        decided _ (Note _ TemplateF{..})  = Map.unionsWith Map.union templateParams
        decided _ x                       = Map.unionsWith Map.union x
```

Type: `Map QualifiedName (Map (NotedExp (Typed n) (ParseError s e)) (Typed n))`.

* **Outer key** = the template's fully-qualified name.
* **Inner key** = the argument-list AST node `b` (a `SeqF`). This is the memoization / dedup key, and
  because `Ord (Note n f a)` ignores the annotation (`Parser/Syntax.hs:597-599`) it is **structural
  equality of the argument expressions, ignoring source spans *and* inferred types**. This is what
  makes `Foo<4>` written in two different files collapse to one instance.
* **Inner value** = the note (span + type) of *one* of the `TemplateInstance` sites. `Map.union` is
  left-biased, so the surviving note is determined by the traversal/fold order — effectively "some"
  instantiation site, not a merge of all of them.
* `all Map.null x` means "no undecided instances nested inside my arguments" — an instance whose
  arguments still contain undecided instances is postponed to the next iteration.
* `indirectInstances` also collects instances that appear inside the template's *parameter list* once
  the arguments are substituted (`resolveTemplateParam`, `TypeCheck.hs:364-378`, which runs
  `resolveTypeParam` → `inferType'` → `templateTypeCheck` → `resolveTemplateInstance` → `inferType'`,
  `TypeCheck.hs:357-362`).
* Instances inside a `static if`'s branches, a `static for`'s body, or a template's *declaration* are
  deliberately not collected — only the condition / limit / parameter list is scanned
  (`Template.hs:105-107`).

Resolution predicates: `templateResolved` (`TypeCheck.hs:299-312`), `templateArgsResolved`
(`TypeCheck.hs:323-329`), `templateArgResolved` (`TypeCheck.hs:314-321` — a type, template, function,
or a fully-resolved `constexprResolved` value per `Constexpr.hs:385-390`).

### 6.4 Instantiation

```haskell
-- Template.hs:110-140
    instantiate t@TemplateF{..}
        | Typename <- templateDecl = t
        | null templateInstances = t
        | otherwise = SeqF $ map makeInstance templateInstances ++ [copyNote t templateDecl]
```

* A `template<…> typename X` template-template parameter is never expanded (`Template.hs:113`).
* The template definition is **kept** after its instances (`Template.hs:115`) so later iterations can
  add more instances.
* `makeInstance (args@(Seq args'), n)` (`Template.hs:125-139`):
  1. `instanceDecl = renote mangleDeclName templateDecl` — the declared name gets the mangled suffix
     (`Template.hs:130,139`);
  2. `desugarWithNote n rewrite instanceDecl` — rewrite the body **and merge the instantiation-site
     note `n` into every node** (`Desugar.hs:91-94`; `Src`'s `Semigroup` builds a `SrcStack`,
     `Parser/Syntax.hs:623-626`) so diagnostics inside an instance point at both definition and use;
  3. `rewrite` clauses (`Template.hs:133-138`):
     * a self-referential `TemplateInstance` of the same template keeps its *original* head `a` with
       the rewritten arguments `b`;
     * a `ScopedNameF` naming the template itself → `mangleTemplateScopedName`;
     * a `ScopedNameF` *qualified by* the template → its qualifier is mangled;
     * otherwise `resolveTypeParam t args'` (`TypeCheck.hs:331-337`): `TypeParamF s _ _ index` whose
       `s` equals the template's qualifier is replaced by `args !! index`; everything else goes through
       `removeNestedTypeIdentifier` (`Desugar.hs:123-129`);
  4. `desugar (modifyDeclScopeName mangleScope)` — every `declScopeName`-bearing node has the
     template's name component replaced with the instance name via `setAt` (`Template.hs:126,131-132`,
     `Internal.hs:43-46`; the node list `modifyDeclScopeName` touches is `Desugar.hs:139-162`:
     `CaptureF, FuncParamF, StructF, EnumConstantF, EnumF, UnionF, AliasF, ClassF, VariableF,
     FunctionF, ThisF, NestedScopeF, DecltypeF, LambdaF, FunctionDeclF, TypeIdentifierF, TypeParamF,
     ScopedNameF`);
  5. `setTypeOfInstance templateQualifiedName (zip (map getName templateParams) args')`
     (`Type.hs:426-431`) tags the instance node with `TInstance TUnresolved name argBindings`.

```haskell
-- Template.hs:158-164
    resolve (TemplateInstanceF a b) | b `Map.member` Map.findWithDefault Map.empty templateQualifiedName decidedInstances =
        mangleTemplateScopedName (unNote $ unfix $ fromJust template) b $ unNote $ unfix a
```

Uses the same structural key. `instantiate . resolve` is a single bottom-up `desugar`, so at each node
`resolve` (rename uses) runs first, then `instantiate` (expand definitions).

### 6.5 Deduplication

```haskell
-- Template.hs:144-156
    deduplicateInstances (SeqF a) = SeqF (nubBy dup a)
      where
        dup (NotedExp _ t1) (NotedExp _ t2) =
            userDefinedTypes t1 t2
         && getQualifiedName t1 == (getQualifiedName t2 :: [String])
        userDefinedTypes ClassF{} ClassF{} = True
        userDefinedTypes StructF{} StructF{} = True
        userDefinedTypes UnionF{} UnionF{} = True
        userDefinedTypes AliasF{} AliasF{} = True
        userDefinedTypes TemplateF{} TemplateF{} = True
        userDefinedTypes FunctionF{} FunctionF{} = True
        userDefinedTypes _ _ = False
```

Complete list of node kinds subject to dedup: `ClassF, StructF, UnionF, AliasF, TemplateF, FunctionF`,
and only when both sides are the *same* kind with the *same qualified name*. It runs
(a) inside `instantiate` for every non-template node (`Template.hs:142`), and (b) as a final whole-tree
pass on the way out (`Template.hs:57`). It is `nubBy` — quadratic per `SeqF`, and scoped to a single
`SeqF`, so it cannot merge duplicates that live in different sequences.

### 6.6 Name mangling — the complete grammar

```haskell
-- compiler/hs/lib/Language/Kanagawa/Mangle.hs:17-19
mangleTemplateScopedName :: Exp n e -> NotedExp n e -> Exp n e -> Exp n e
mangleTemplateScopedName template args (ScopedNameF n a b) = ScopedNameF n a $ mangleTemplateIdentifier template args b
mangleTemplateScopedName _ _ _ = undefined
```

```haskell
-- Mangle.hs:21-29
-- Mangling algorithm must generate unique names for different sets of arguments.
-- 1) Mangled arguments are wrapped between <| and |>
-- 2) Strings contributed by the compiler are prefixed with $ (dollar sign).
-- 3) User defined names and scalar literals are prefixed with @ (ampersand).
mangleTemplateIdentifier :: Exp n e -> NotedExp n e -> NotedExp n e -> NotedExp n e
mangleTemplateIdentifier template = renote . mangleIdentifier'
  where
    mangleIdentifier' args (IdentifierF a) = IdentifierF $ suffixName ("<|" <> cata mangle args <> "|>") a
    mangleIdentifier' _ _ = undefined
```

`suffixName x = mapName (<> x)` (`Desugar.hs:164-165`) — the mangled tail is **appended** to the
declared name. The algebra runs over the whole argument `SeqF`; `mangle (Seq e) = concat e`
(`Mangle.hs:56`) — **no separator between arguments**.

Complete production table (`Mangle.hs:31-64`; the `cata` algebra is over the one-level
`Language.Kanagawa.Parser.Syntax.Pattern` synonyms, so `x`, `y`, `z` are already-mangled `String`s):

| Node | Production | Line |
|---|---|---|
| `isClosure` predicate | `getQualifiedName template == data'closure'core'Closure` (`Type.hs:121-122`) | `Mangle.hs:31` |
| `Auto` | `"$auto"` | 33 |
| `Array x y z` | `"$array" <> x <> y <> z` | 34 |
| `Attr x y` | `"@" <> show x <> y` (`show :: Attribute -> String`, `Parser/Syntax.hs:136-145`) | 35 |
| `BoolLiteral x` | `"@" <> show x` → `"@True"` / `"@False"` | 36 |
| `Const x` | `"$const" <> x` | 37 |
| `Designator x y` | `"@" <> x <> y` | 38 |
| `EnumValue x _` | `x` (the *value* part is dropped) | 39 |
| `FlagAttr x` | `"$" <> show x` (`Parser/Syntax.hs:166-179`) | 40 |
| `FloatLiteral x` | `"@" <> show x`, `x :: Float` (`Parser/Syntax.hs:352`) | 41 |
| `FunctionType x y z` | `""` if `isClosure`, else `"$fun" <> x <> y <> z` | 42-44 |
| `FunctionTypeParam x y _` | `x <> y` (the parameter name is dropped) | 45 |

#### The `show :: Float -> String` embedding

`FloatLiteralF` carries a Haskell `Float` (single precision, `Parser/Syntax.hs:352`), and the mangler
embeds `show x` verbatim (`Mangle.hs:41`). GHC's `Show Float` uses `showFloat`, which produces the
*shortest decimal string that round-trips* to the same `Float`, always with a decimal point, and
switches to scientific notation outside `[0.1, 10^7)`. Consequences a Rust implementation must
reproduce exactly, or template instance names will not match:

* `1` → `"1.0"`, `0.5` → `"0.5"`, `100` → `"100.0"`, `1e7` → `"1.0e7"`, `0.01` → `"1.0e-2"`;
* negative zero → `"-0.0"`; negatives keep the leading `-`, e.g. `"-3.0"`;
* `Infinity`, `-Infinity`, `NaN` are spelled exactly that way;
* the exponent form is `d.dddeN` (no `+`, no zero padding), and the mantissa always has at least one
  fractional digit.

In Rust the closest primitive is `f32`'s `Display`/`ryu` shortest round-trip form, but `f32::to_string`
prints `1` for `1.0f32` and `inf`/`NaN` differently — **a bespoke formatter is required**.

## 7. Structural equality: `Note`'s `Eq`/`Ord`

```haskell
-- compiler/hs/lib/Language/Kanagawa/Parser/Syntax.hs:586-599
data Note x f a =
    Note
    { note   :: x       -- ^ the note
    , unNote :: !(f a)  -- ^ the original functor
    }
    deriving (Show,Functor,Foldable,Traversable)

-- Equality ignores annotation
instance Eq (f a) => Eq (Note n f a) where
    (==) a b = unNote a == unNote b

-- Ordering ignores annotation
instance Ord (f a) => Ord (Note n f a) where
    (<=) a b = unNote a <= unNote b
```

`Fix`'s instances are derived through (`Recursion.hs:47-48`), so `Eq`/`Ord` on `NotedExp n e` is a
structural comparison of the `ExpF` spine, with the note skipped **at every level**. Since the note is
`Typed n = Typed Type Src` (`Type.hs:445-450`, `noteType` at `Type.hs:973-976`), the comparison ignores
**both the source span and the inferred type**. `ExpF`'s own `Eq`/`Ord` are derived
(`Parser/Syntax.hs:584`) — so the `Ord` on nodes is *constructor-declaration order first*, then
field-by-field — and leaf payloads — `Name`, `QualifiedName`, `Int`, `Integer`, `Float`,
`Bool`, `String`, `Maybe LiteralType`, the enum types, and `e` (the error payload) — *are* compared.

### Every place it matters

1. **`decidedInstances` inner map key** — `Template.hs:88-96`. `Map.singleton b $ note $ unfix e`
   where `b :: NotedExp` is the argument `SeqF`. This is the template instance dedup/memo key.
   The `Ord (Token s), Ord s, Ord e` constraints on `instantiateTemplates` (`Template.hs:48`) exist
   solely to give `ParseError s e` an `Ord` (`Error.hs:66`) so the AST is orderable.
2. **`resolve`'s membership test** — `Template.hs:159`: `b \`Map.member\` …`. A use site is renamed to
   the mangled instance name iff its argument tree is structurally equal (span/type-blind) to a decided
   one.
3. **Template-template parameter matching** — `TypeCheck.hs:252-254`:
   `matchParamKind t1 (TemplateParam _ t2 _ _ _) | t1 == t2 = True | otherwise = theType t1 == theType t2`.
   First a structural AST comparison, then a `Type` comparison (`Type` derives `Eq`, `Type.hs:278`).
4. **Duplicate designator detection** — `TypeCheck.hs:65`:
   `dupDesignator (Designator a _) (Designator b _) = a == b`, driving the
   `InitializerOverrides` warning (`TypeCheck.hs:60-67`).
5. **Where it explicitly does *not* apply**: `deduplicateInstances` compares qualified *names* and node
   kinds, not trees (`Template.hs:144-155`); `inferType`'s fixpoint compares an `[Integer]` measure
   (`Type/Inference.hs:34,41`); symbol tables are `HashMap QualifiedName` (`Symbols.hs:26`).
6. **Error dedup in the driver is span-sensitive**: `Main.hs:81` does `nub $ errors $ unnoteType
   desugared`, over `[(Src, ParseError s e)]`; `Src` has a derived `Eq` (`Parser/Syntax.hs:610-621`),
   so two identical messages at different locations both survive — and two identical messages at the
   *same* location collapse, which matters because template instantiation copies bodies.

### Rust implication

A `NodeId`-based arena cannot use `#[derive(PartialEq)]` on the node struct if it stores a span/type.
The dedup key must be a *structural hash/eq* that walks the spine and skips the side tables. See §11.

## 8. `static if` / `static for` elaboration and constexpr evaluation

### Where constexpr evaluation is invoked

Exactly two call sites, both in `Type/Inference.hs`:

```haskell
-- Type/Inference.hs:23-25 (inferType')
inferType' symbols = cata infer
  where
    infer = inferExpType symbols . unfix . evaluateConstexpr symbols

-- Type/Inference.hs:47-50 (inferExpTree, used by inferType)
inferExpTree symbols = inferExpTree' infer
  where
    infer = staticControl . unfix . evaluateConstexpr symbols . unfix . inferExpType symbols
```

* `inferType'` — **no `staticControl`**. Used by `resolveTemplateParamType`
  (`TypeCheck.hs:357-362`) and `resolveTemplateInstance` (`TypeCheck.hs:343`), i.e. while deciding
  whether a template's arguments are resolvable.
* `inferExpTree` / `inferType` — infer → fold → elaborate static control, bottom-up, per node.

So: **constexpr evaluation only ever happens inside `inferType`/`inferType'`.** Frontend execution-order
pass #6 (`Frontend.hs:69`), plus T5 and T8 inside the template loop (`Template.hs:72,75`), plus the
post-instantiation `inferType` (`Template.hs:58`), plus the template-argument machinery.

`evaluateConstexpr` (`Constexpr.hs:128-356`) folds, in this complete set of cases:
`TemplateInstanceF` argument resolution (aliases → definitions, const aggregates → initializer lists,
function names → their identifiers), `ArrayF` dimensions containing enum values, `ScopedNameF` over a
class/enum, `BitOffsetF`, `ByteOffsetF`, `UnaryF Clog2`, `BinaryF` (integer, bool, string, type-level
`<:` comparisons, and the absorbing identities `x & 0`, `x | ~0`, `x || True`, `x && False`),
`UnaryF Neg/Invert/BitSizeof/ByteSizeof/Not`, `NamedValueF` of a const variable or enum constant,
`ParamIntF`, `ParamUintF`, `DecltypeF`, `CastF`, `MuxF`, `StaticF`. Note the guard at
`Constexpr.hs:295-296`: everything below that line requires `typeResolved n`.

### `static if`

Syntax: `Parser.hs:593-595` — `static if (expr) X else Y`, where each branch may be a
`NestedScope` (`Parser.hs:467`). It appears in three grammatical positions:
declarations (`Parser.hs:247`), class members (`Parser.hs:344`), statements (`Parser.hs:500`), and
switch blocks (`Parser.hs:604`).

Elaboration (`Constexpr.hs:44-48`):

```haskell
    eval (StaticIfF (BoolLiteral True) x _) =
        unNote $ unfix $ removeNestedScope x

    eval (StaticIfF (BoolLiteral False) _ x) =
        maybe (SeqF []) (unNote . unfix . removeNestedScope) x
```

`removeNestedScope` (`Constexpr.hs:358-370`) splices the branch's `NestedScopeF` away and rewrites every
`declScopeName` and `ScopedNameF` that referenced the removed scope component.

Because `inferExpTree'` only descends into a `StaticIfF`'s *condition* (`Type/Inference.hs:64`), the
selected branch is typed on a **later iteration** of the `inferType` fixpoint. A `StaticIfF` whose
condition never folds to a `BoolLiteral` survives to execution-order pass #16 and becomes
`"static if predicate did not evaluate to a boolean constant"` (`Frontend.hs:406`).

### `static for`

Syntax: `Parser.hs:591` — `static for (const T i : limit) stmt`, parsed in a `localScoped` (a `$quasiN`
scope, `Parser.hs:147-156,131-133`).

Elaboration (`Constexpr.hs:50-124`) has two outcomes, selected by an *induction-variable dependency
analysis* `inductionVarDependency` (`Constexpr.hs:62-84`) over the three-valued lattice
`Independent | Dependent | DependentConstexpr` (`Constexpr.hs:30-39`):

* a reference to the induction variable's name marks the subtree `Dependent` (`Constexpr.hs:82-83`);
* if a `Dependent` subtree sits under any of `TemplateInstance`, `Array`, `ParamInt`, `ParamUint`,
  `StaticAssert`, `Static`, `UnrolledFor` (via `forLimit`), `StaticFor` (via `forLimit`), or
  `StaticIf` (via `staticIfCond`), the whole thing becomes `DependentConstexpr`
  (`Constexpr.hs:64-81`) — that is the complete trigger list.

Then:

```haskell
    eval (StaticForF a b c) = case inductionVarDependency of
        DependentConstexpr
            | IntLiteral _ i <- b -> NestedScopeF (init bodyDeclScopeName) (new $ IdentifierF $ last bodyDeclScopeName) $ iterations i
            | otherwise           -> e
        _                         -> UnrolledForF a b c
```

* **Not `DependentConstexpr`** → `UnrolledForF` — the loop is handed to the backend as a runtime
  construct with a static trip count; the body is emitted once.
* **`DependentConstexpr` with a literal limit** → fully unrolled at compile time into a `NestedScopeF`
  containing one `NestedScopeF` per iteration named `"$" ++ inductionVarName ++ show i`
  (`Constexpr.hs:88-95`). Each iteration:
  * gets its own copy of the induction variable initialized to `IntLiteralF Nothing i`
    (`Constexpr.hs:97-99`);
  * has all `declScopeName`s re-rooted into the iteration scope (`fixDeclScopeName`,
    `Constexpr.hs:102-104`);
  * has `ScopedNameF`s pointing at the loop body or at the induction variable rewritten
    (`fixScopedName`, `Constexpr.hs:106-111`);
  * **has every lambda renamed** by suffixing the iteration tag, so `?lambda0` becomes
    `?lambda0$i3` etc. (`replicateLambda`, `Constexpr.hs:113-123`) — otherwise the per-iteration lambda
    functions hoisted later would collide.
* **`DependentConstexpr` with a negative literal limit** → `"Negative iteration count is invalid: N"`
  (`Constexpr.hs:85-87`).
* **`DependentConstexpr` with a non-literal limit** → the node is left as `StaticForF`. Nothing later
  diagnoses this (`StaticForF` is absent from `unresolved`, `Frontend.hs:400-407`) — see Open questions.

## 9. Lambda / closure lowering, HOF lowering, hoisting, abbreviated templates

All four live in the template loop's sub-pipeline (§6.2) except `higherOrderFunctions`, which is
frontend pass #2.

### 9.1 The closure representation

`library/data/closure/core.k:9-10`:

```
template <typename FunctionType, FunctionType fn, typename Capture>
using Closure = Capture;
```

A closure **value** is just the capture struct; the closure **type** carries the target function's name
as a template argument. `Type.hs:265` `TClosure QualifiedName Type Type QualifiedName` =
(function qualified name, function type, capture type, alias instance name); built at
`Type.hs:1175-1178` when an `AliasF` instance of `Closure` is typed. Subtyping compares only the
function name (`Type.hs:340-341`). Capture construction uses `make_capture0`
(`library/data/closure/core.k:13`) through `make_capture21` (`library/data/closure.k:6-26`); the
selection is by arity (`Function.hs:153-155`), and the zero-capture case comes from the `core` module,
all others from `data.closure`.

### 9.2 `addLambdaWrappers` (T1) — `Function.hs:366-423`

Wraps a *named function passed as an argument* into a lambda so that the callee (which was turned into
a closure-taking template by `higherOrderFunctions`) receives a uniform closure.

Before:
```
inline void Go(() -> void Do) { Do(); }
inline void f() { }
… Go(f);
```
After (sketch — `Function.hs:398-421`):
```
… Go([] () -> void { return f(); });     // free function
… Go([this] () -> void { return this.m(); });  // member function: captures `this`
```

Details: the synthetic lambda is named `concatMap ('$':) ("wrapper" : qualifiedNameOfTarget)` — i.e.
`$wrapper$Ns$f` (`Function.hs:400`); its parameters are copied from the callee's declaration
(`Function.hs:388-393`) or synthesized from a function-typed variable's type with names
`$wrapper_param0…` (`Function.hs:379-386`); `lambdaCaptures` is `[ThisF]` for a member function and
empty otherwise (`Function.hs:407-409`); the body is `return <call>` forwarding all parameters
(`Function.hs:411-421`). Three symbol shapes are wrapped (`Function.hs:388-394`): `Function`,
`FunctionDecl`, and a `Variable` of function type; `MemberAccess` on a reference-typed object is also
wrapped (`Function.hs:370-372`).

Symbols for this pass are built with `NoTemplate` (`Template.hs:79`, `Symbols.hs:57-59`), so template
declarations do not shadow ordinary ones.

### 9.3 `desugarLambdas` (T2) — `Function.hs:189-262`

For each of `FunctionF`, `LambdaF`, global `VariableF`, and each branch of a `StaticIfF`
(`Function.hs:192-201`), the pass:

1. collects all lambdas in that body, **not descending into nested `Function`, `Lambda`, `StaticIf`,
   `StaticFor`** (`Function.hs:228-234`);
2. prepends, for each lambda, two declarations (`Function.hs:236-262`):
   * `AliasF declScopeName (DecltypeF (makeCapture l)) (name <> "$capture")` — the capture struct type
     (`Function.hs:241-243`, `Function.hs:222`);
   * a `FunctionF … LambdaFunction … inline …` with the same name, whose parameter list has an extra
     leading `FuncParamF` named `<name>$capture_param` of the capture type (`Function.hs:246-254`), and
     whose body begins with one `VariableF … AutoF … DeclareLocal` per capture, initialized to
     `<capture_param>.x<i>` (`Function.hs:255-261`);
3. replaces each `LambdaF` expression in place with `makeClosure` (`Function.hs:161-170`):
   `CastF (Closure<FnType, fn, CaptureType>) (make_captureN(c0, c1, …))` where the call is built by
   `makeCapture` (`Function.hs:145-159`) and `this` captures are forwarded as `ThisF`
   (`Function.hs:156`);
   for a *generic* lambda (any `auto` parameter, `Function.hs:186-187`) the function-type argument is
   spelled explicitly instead of `decltype` (`Function.hs:207,212-216`).

Before:
```
inline void f() {
    uint32 x = 1;
    auto g = [x](uint32 y) -> uint32 { return x + y; };
}
```
After (sketch):
```
inline void f() {
    using ?lambda0$capture = decltype(data.closure.make_capture1(x));
    inline uint32 ?lambda0(?lambda0$capture ?lambda0$capture_param, uint32 y) {
        auto x = ?lambda0$capture_param.x0;
        return x + y;
    }
    uint32 x = 1;
    auto g = cast< Closure<decltype(?lambda0), ?lambda0, ?lambda0$capture> >(
                 data.closure.make_capture1(x));
}
```

(Lambda names come from the parser: `indexedName i "?lambda"` per scope, `Parser.hs:434`,
`Parser/SymbolTable.hs:216-225`.)

The `desugarShallow lambdaRef` at `Function.hs:204` returns `Nothing` for `FunctionF` and `StaticForF`
(`Function.hs:218-219`), which — per `Desugar.hs:76-79` — **reverts those subtrees wholesale**, so
lambdas inside a nested function are left for that function's own turn.

### 9.4 `abbreviatedFunctionTemplate` (T3) — `Function.hs:288-311`

An "abbreviated template" is a function with one or more `auto` parameters
(`Parser/Syntax.hs:722-724`).

```
inline void f(auto a, uint32 b, auto c) { … }
```
becomes (`Function.hs:290-292`) a `SeqF` of **two** nodes: a real template *and the original
function*:
```
template <typename a$T, typename c$T>
inline void f(a$T a, uint32 b, c$T c) { … }

inline void f(auto a, uint32 b, auto c) { … }   // left behind; deleted by pass #15
```
The generated `TemplateParamF`s are named `<paramName>$T` with index = the *ordinal among auto
parameters* (`Function.hs:294-300`), and the function's `auto` parameter types are replaced by the
corresponding `TypeParamF` (`Function.hs:304-308`, `typeParam` at `Function.hs:130-132`).
The leftover original is deleted by `removeTemplate` (`Frontend.hs:300-301`).

`abbreviatedFunctionTemplate _ TemplateF{} = Nothing` (`Function.hs:310`) — reverting the subtree, so
an *explicit* template containing an abbreviated function is not touched here.

### 9.5 `moveFunctions` (T4) — `Function.hs:84-128` + `moveToParentScope` `Function.hs:28-82`

Hoists nested declarations to the enclosing scope:

* out of a `FunctionF` body and out of a `NestedScopeF`: every `Function`, `Template _ Function`, and
  `Class` (`Function.hs:97-99,121-124`);
* out of a `ClassF` body: every lambda function, i.e. `Function _ LambdaFunction …` and
  `Template _ (Function _ LambdaFunction …)` (`Function.hs:102,126-128`);
* it also lifts the trailing statement out of `DoWhileF`, `RangeForF` and both arms of `IfF` when the
  body desugared into a `SeqF` (`Function.hs:104-117`) — this is how declarations hoisted out of a loop
  body end up *before* the loop.

Deferred (returned untouched, `Function.hs:88-94`): `Template{}`, abbreviated-template `Function{}`,
`StaticIf{}`, `StaticFor{}`, and `Class{}` in a local scope.

The moved declaration is renamed `"<parent>@<child>"` (`Function.hs:39-40`), its `declScopeName`s are
re-rooted (`Function.hs:47-50`), and references to it from the remaining body are re-qualified
(`fixScopedName`, `Function.hs:80-82`). Crucially, references from the moved code to the *parent's*
members are rewritten into `this`-relative access (`memberAccess`, `Function.hs:52-64`):
a `NamedValueF` resolving to a class-scope `Variable` becomes `MemberAccessF this name` (or is
replaced by the constant's initializer when it is a `Const` with a non-`InitializerList` value —
`Function.hs:55`), and an unqualified call to a member function becomes a `this`-qualified call
(`Function.hs:58-62`).

### 9.6 `closureCalls` (T6) — `Closure.hs:19-26`

```haskell
closureCalls (FunctionCallF a (FunctionSpecifier _ b) c)
    | tIsClosure $ typeOf b = FunctionCallF a function (capture `cons` c)
```

Calling through a closure-typed value `b` becomes a direct call to the closure's target function with
the capture value inserted as the first argument, cast to the capture type
(`Closure.hs:23-25`). This is the counterpart of the extra leading parameter added in §9.3 and §9.2.

## 10. Whole-program vs per-file — where the Rust query boundary goes

The program is a *list* of per-file ASTs throughout the frontend (`Main.hs:70-76`,
`Frontend.hs:34-38`). Three levels of coupling exist:

**(a) Structurally per-file** — `passPar f` maps `f` over files independently
(`Frontend.hs:46`, `Desugar.hs:54-55`); with no symbol argument these are genuinely file-local:

| Execution # | Pass | Cite |
|---|---|---|
| 3 | `captureThis . reifyEnums` | `Frontend.hs:72` |
| 5 | `intrinsics` | `Frontend.hs:70` |
| 10 | `cata typeErrors` | `Frontend.hs:65` |
| 11 | `unresolvedFunctionTemplateArgs` | `Frontend.hs:64` |
| 15 | `removeTemplate` | `Frontend.hs:60` |
| 17 | `deduceAuto` | `Frontend.hs:58` |
| 18 | `interpolatedStringPost` | `Frontend.hs:57` |

Caveat: #17 and #18 are file-local *rewrites* but consume types that were computed whole-program.

**(b) Per-file map over a whole-program symbol table** — `withSymbols` + `passPar`. The rewrite is
file-local; the *input* is a program-wide `HashMap QualifiedName (NotedExp …)` (`Symbols.hs:26,37-41`):

| Execution # | Pass | Cite |
|---|---|---|
| 1 | early normalization (`redundantNameScope` needs symbols) | `Frontend.hs:74-79` |
| 2 | `higherOrderFunctions` | `Frontend.hs:73` |
| 4 | `deduceTemplateArgs` | `Frontend.hs:71` |
| 12 | `unresolvedTemplates` | `Frontend.hs:63` |
| 14 | `validateExtern` | `Frontend.hs:61` |
| 16 | `postDesugar` | `Frontend.hs:59` |
| 19 | `validateProgram` | `Frontend.hs:55-56` |

**(c) Genuinely whole-program (blocks incrementality)** — the function's *type* is
`[NotedExp] -> [NotedExp]` and it derives a program-wide fact or iterates globally:

| Execution # | Pass | Why | Cite |
|---|---|---|---|
| 6 | `inferType` | global fixpoint over the concatenated unresolved-count vector; symbol table rebuilt every iteration | `Type/Inference.hs:30-45` |
| 7 | `trimExternClasses` | `externClasses` is a `Set` unioned across all files | `Frontend.hs:331-335` |
| 8 | `instantiateTemplates` | `decidedInstances` is a program-wide map; instances defined in file A are materialized into the file that declares the template | `Template.hs:88`, `Template.hs:53-58` |
| 9 | `undefinedSymbols` | needs the closed-world symbol map to prove a name is *not* defined, plus the edit-distance hint search over all symbols | `Frontend.hs:87-153` |
| 13 | `validateExportableClasses` | `exportableClasses` map unioned across all files, transitively following public members | `Frontend.hs:351-366` |

**Query-boundary recommendation for the Rust rewrite:**

* Per-file salsa queries: parse, lower-to-HIR, and the pass-(a) rewrites.
* One program-wide `symbols(crate)` query feeding the pass-(b) rewrites; those stay per-file-cached but
  are invalidated whenever the symbol table's *relevant slice* changes (use a fingerprint per
  qualified-name bucket rather than the whole map).
* Passes (c) are the incrementality wall. `inferType` + `instantiateTemplates` are one mutually
  recursive whole-program fixpoint (instantiation calls `inferType` internally at
  `Template.hs:58,72,75`), so they should be a single query producing "the instantiated program".
  There is no way to make template instantiation per-file: the memo table is keyed by
  (template qualified name, structural argument tree) across the whole program (`Template.hs:88-96`).

## 11. Proposed Rust pass pipeline design

### 11.1 HIR arena

```rust
// crates/kg-hir/src/arena.rs
#[derive(Copy, Clone, PartialEq, Eq, Hash, Debug)]
pub struct NodeId(u32);

/// The single 93-constructor functor, mirroring
/// kanagawa/compiler/hs/lib/Language/Kanagawa/Parser/Syntax.hs:282-584 (ExpF).
/// Children are NodeId, never Box — the tree is a flat arena so passes can
/// rebuild bottom-up without cloning subtrees.
#[derive(Clone, PartialEq, Eq, Hash, Debug)]
pub enum ExpKind {
    Seq(IdList),
    FlagAttr(Flag),
    IntAttr(Attribute, NodeId),
    // … one variant per ExpF constructor, same field order …
    Error(DiagId),
}

pub struct Hir {
    kinds:  Vec<ExpKind>,           // indexed by NodeId
    // --- side tables: deliberately NOT part of node identity ---
    spans:  Vec<SrcStack>,          // Note.note, Parser/Syntax.hs:586-591
    types:  Vec<Ty>,                // Typed.typeof,  Type.hs:445-450
    roots:  Vec<NodeId>,            // one per source file (Main.hs:70-76)
    lists:  Vec<NodeId>,            // backing store for IdList
    names:  Interner<Name>,         // Name = Hashed String, Parser/Syntax.hs:51-52
}
```

The split between `kinds` and `{spans, types}` *is* the Haskell `Note` semantics: `Eq`/`Ord` on
`Note` ignore the annotation (`Parser/Syntax.hs:594-599`), so `ExpKind`'s derived `PartialEq` and
`Hash` must never see a span or a type.

Structural identity, needed for the template memo key (§7):

```rust
/// Structural key used for template-instance deduplication.
/// Mirrors Ord (Note n f a) at Parser/Syntax.hs:597-599: the note (span + inferred
/// type) is ignored at EVERY level of the tree.
#[derive(Clone, PartialEq, Eq, Hash)]
pub struct StructuralKey(Box<[u8]>); // canonical postorder encoding of the subtree

impl Hir {
    pub fn structural_key(&self, n: NodeId) -> StructuralKey { /* postorder encode kinds only */ }
}
```

Hash-consing the whole arena would give this for free, but it changes `NodeId` sharing semantics; a
separate on-demand key keeps rewrites cheap and is closer to the reference behavior.

### 11.2 The pass trait

```rust
pub enum PassScope {
    /// Rewrites one file's tree with no cross-file input.
    PerFile,
    /// Rewrites one file's tree, reading the whole-program symbol table.
    PerFileWithSymbols,
    /// Consumes and produces the whole program list.
    WholeProgram,
}

pub struct PassCx<'a> {
    pub hir:      &'a mut Hir,
    pub symbols:  &'a SymbolTable,   // Symbols.hs:26 — rebuilt per `withSymbols` pass
    pub diags:    &'a mut Diagnostics,
    pub opts:     &'a FrontendOpts,
}

pub trait Pass {
    const ID: PassId;
    const NAME: &'static str;
    /// `Frontend.hs:42-44`: a pass is skipped entirely once the error flag is set.
    const SCOPE: PassScope;
    /// `Frontend.hs:48-52`: only passes that set the flag return `true` here.
    const SETS_ERROR_FLAG: bool = false;

    fn run(cx: &mut PassCx<'_>) -> PassOutcome;
}

pub struct PassOutcome { pub has_errors: bool }
```

Error-flag threading reproduces `pass`/`passPar`/`checkPar` exactly: run nothing once
`has_errors` is set (`Frontend.hs:43,49`); only `EarlyNormalize`, `InstantiateTemplates` and
`UndefinedSymbols` may set it (`Frontend.hs:50`, `Template.hs:56`, `Frontend.hs:87`).

### 11.4 Reproducing `--frontend-passes` for bisection

Because `FRONTEND_PASSES` is stored in execution order, the Haskell "drop from the front" becomes a
prefix take:

```rust
/// `--frontend-passes=N` (Options/CmdArgs.hs:104, default maxBound::Int).
///
/// Reference: `drop (length passes - frontendPasses) passes` (Frontend.hs:38) removes
/// entries from the front of a source list whose LAST entry runs first — i.e. it keeps
/// the N earliest-executing passes. `drop` returns the whole list for n <= 0, so any
/// N >= 19 means "all".
pub fn selected_passes(n: u32) -> &'static [PassId] {
    let n = (n as usize).min(FRONTEND_PASSES.len());
    &FRONTEND_PASSES[..n]
}
```

with the analogous `selected_template_passes(m)` gated on `template_iterations == 0`
(`Template.hs:62-63`). The template loop:

```rust
fn instantiate_templates(mut prog: Program, mut iters: u32, tpasses: u32, cx: &mut PassCx)
    -> (Program, bool)
{
    loop {
        // Template.hs:60-63
        let sub = if iters == 0 { selected_template_passes(tpasses) } else { &TEMPLATE_PASSES[..] };
        prog = run_all(sub, prog, cx);

        if cx.symbols_of(&prog).has_error_symbol() { return (prog, true); }   // Template.hs:56,83-84
        let decided = decided_instances(&prog, cx);                            // Template.hs:88-108
        if iters == 0 || decided.is_empty() {
            return (dedup_instances(prog), false);                             // Template.hs:57,144-156
        }
        prog = infer_type(rewrite_instantiate_and_resolve(prog, &decided));     // Template.hs:58
        iters -= 1;
    }
}
```

`decided_instances` is `FxHashMap<QualifiedName, IndexMap<StructuralKey, (SrcStack, NodeId)>>`;
`IndexMap` (already a workspace dependency) preserves the left-biased first-writer-wins semantics of
`Map.union` (`Template.hs:88,94`) *and* gives deterministic instance ordering, which the Haskell
`Data.Map` provides via key ordering — see Open questions on whether instance *emission order* is
observable.

Mangling gets its own module with a hand-written `fn show_float(f: f32) -> String` reproducing GHC
`Show Float` (§6.6), and a `#[test]` table pinned against the reference compiler's output.

## 12. Where `doc/compiler-design-reference.md` §3.2 is wrong or incomplete

`doc/compiler-design-reference.md:55-79`.

1. **Order is presented backwards.** `doc/compiler-design-reference.md:59-75` says "The current pass
   sequence includes… " and then lists the passes in *written* order — program validation first,
   final-validation last. The actual execution order is the exact reverse (`Frontend.hs:38`;
   derivation in §3). Concretely, the doc implies `validateProgram` runs first when it runs **last**
   (pass 19), and implies the typed-literal/interpolated-string/redundant-scope validation runs last
   when it runs **first** (pass 1).
2. **"among other steps"** (`doc/compiler-design-reference.md:59`) — the list is presented as partial;
   it is also *inaccurate as a grouping*. It merges `unresolvedTemplates` with `removeTemplate`
   ("template removal and unresolved-template handling") though they are two separate list entries
   executing at positions 12 and 15, three passes apart, with `validateExportableClasses` and
   `validateExtern` in between.
3. **Missing passes.** `intrinsics` is called "intrinsic lowering" but it lowers nothing — it only
   annotates five hard-coded names with function types (`Type.hs:1069-1084`). `typeErrors`
   (`Frontend.hs:65`) and `unresolvedFunctionTemplateArgs` (`Frontend.hs:64`) do not appear at all.
4. **The doc says nothing about the error flag**, which changes observable behavior: after pass 1 sets
   it, passes 2-19 are skipped entirely (`Frontend.hs:42-52`), so the compiler's diagnostics for a
   program with an early error are a strict subset of what the pass list suggests.
5. **The doc says nothing about `instantiateTemplates` being a fixpoint with its own nine-pass
   sub-pipeline** (`Template.hs:53-81`), which is where lambda lowering, function hoisting and
   abbreviated-template expansion actually happen. Reading only §3.2, one would place those in the top
   level list; they are not there.
6. **`--frontend-passes` / `--template-passes` / `--template-iterations` are not mentioned**, nor the
   fact that `--template-passes` is inert unless `--template-iterations` is finite (§6.2).

Everything else in §3.2 checks out: `desugarPasses` is indeed the authoritative list
(`Frontend.hs:54-80`), the pipeline is encoded in Haskell rather than data, and the frontend does
produce a fully typed, lowered AST before any ParseTree node is created (`Main.hs:84,97`).

## 13. Traps a Rust implementer will otherwise miss

1. `foldr ($)` reverses both pass lists (`Frontend.hs:38`, `Template.hs:60`).
2. `desugar (f . g . h)` applies `h` first at each node — the textual order inside a fused pass is also
   reversed (`Frontend.hs:74-79`, `Frontend.hs:176-183`, `Frontend.hs:72`).
3. `desugarShallow`'s `Nothing` **reverts the whole subtree to its pre-rewrite form**, it does not
   merely "skip" (`Desugar.hs:76-79`); used at `Frontend.hs:191`, `Frontend.hs:327`,
   `Function.hs:218-219`, `Function.hs:310`.
4. `Note`'s `Eq`/`Ord` ignore span *and* type (`Parser/Syntax.hs:594-599`) — the template memo key is
   span/type-blind structural equality (`Template.hs:96`).
5. `mangle (IntLiteral _ x)` discards the literal's width/signedness (`Mangle.hs:50`), so
   `F<uint8(5)>` and `F<int32(5)>` mangle identically.
6. `mangle` has no separator between arguments (`Mangle.hs:56` `concat`), and compiler-generated names
   legitimately contain `@` (module namespaces `Parser/Syntax.hs:273-274`, hoisted names
   `Function.hs:39`), so the "@ prefixes user names" invariant does not by itself guarantee injectivity.
7. `mangle (FunctionType …) | isClosure = ""` (`Mangle.hs:42-44`) — closure instances deliberately drop
   their function-type argument from the mangled name.
8. `mangle _ = undefined` (`Mangle.hs:64`) — an unexpected argument node kind aborts the compiler with
   a Haskell `undefined`, not a diagnostic.
9. `show :: Float -> String` is embedded verbatim in mangled names (`Mangle.hs:41`); Rust's
   `f32::to_string` does not match (§6.6).
10. `--template-passes` is a no-op unless `--template-iterations` is small enough to reach zero
    (`Template.hs:62-63`).
11. `drop` of a negative count returns the whole list, which is what makes the `maxBound` defaults work
    (`Frontend.hs:38`, `compiler/hs/app/Options/CmdArgs.hs:104-106`).
12. `inferType` stops when the unresolved-node count *vector stops changing*, not when it reaches zero
    (`Type/Inference.hs:34`); it is legal for the program to still contain unresolved nodes.
13. `inferExpTree'` deliberately does not descend into lambda bodies, template declarations, static-if
    branches, or functions with unresolved/function-typed parameters (`Type/Inference.hs:52-68`) — a
    naive "type everything bottom-up" Rust port will diverge (and will try to type template bodies with
    unsubstituted type parameters).
14. `abbreviatedFunctionTemplate` emits the template **and** keeps the original function
    (`Function.hs:290-292`); the leftover is deleted 12 passes later by `removeTemplate`
    (`Frontend.hs:300-301`). Between those points the symbol table contains both.
15. `instantiate` keeps the template definition after its instances (`Template.hs:115`), so template
    definitions are alive until pass 15.
16. `desugarWithNote` merges the instantiation-site note into every node of an instance
    (`Template.hs:127`, `Desugar.hs:91-94`), producing a `SrcStack` (`Parser/Syntax.hs:623-626`).
    Diagnostics inside template instances therefore have a *location stack*, and `Main.hs:81`'s `nub`
    dedups on that whole stack.
17. `getSymbols''` builds the map as `HashMap.fromList . reverse . para update` (`Symbols.hs:44`):
    the parent is emitted before its children, and `reverse` + `fromList`'s last-wins mean the
    **outermost / first-in-source** declaration wins a name collision.
18. `getSymbols''` with `NoTemplate` drops the template's own symbol via `tail` on the accumulated list
    (`Symbols.hs:57-59`) — a positional hack that depends on the parent-before-children emission order.
19. Struct and union bodies contribute **no** symbols (`Symbols.hs:48-49`, `const mempty`), and with
    `TemplateDecl` neither do template bodies (`Symbols.hs:46-47`).
20. `Class` inserts **two** symbol entries: its name and `<name>::$this` (`Symbols.hs:66`,
    `thisName = "$this"` at `Parser/Syntax.hs:267-268`).
21. `static for` that is `DependentConstexpr` with a non-literal limit silently survives as `StaticForF`
    — nothing in `unresolved` catches it (`Constexpr.hs:53`, `Frontend.hs:400-407`).
22. Static-for unrolling renames every lambda per iteration (`Constexpr.hs:113-123`); skipping that
    produces duplicate hoisted function names.
23. `reifyEnums` emits `prev + 1` *expressions*, not folded integers (`Frontend.hs:207`), so enum values
    depend on constant folding running afterwards.
24. `returnVoid` turns `return f();` into `f(); return;` (`Frontend.hs:293-296`) — a statement-count
    change that any AST-shape assertion downstream must tolerate.
25. `deduplicateInstances` is `nubBy` scoped to a single `SeqF` (`Template.hs:144`) — O(n²) and unable
    to merge duplicates across sequences.

## Open questions

Each names the probe program that would settle it.

1. **Is template *instance emission order* observable in the output?**
   `decidedInstances` is a `Data.Map` keyed by the argument AST, so `Map.toList`
   (`Template.hs:120`) yields instances in the `Ord` order of their argument trees — which is the
   derived `Ord` on `ExpF`, i.e. constructor-declaration order then field order
   (`Parser/Syntax.hs:282-584`). Reproducing that in Rust requires sorting by the same total order, not
   just deduplicating.
   *Probe:* a file instantiating `template<int N> struct S{}` as `S<2>`, `S<1>`, `S<10>` in that source
   order; compile with `--dump-program` and observe the order of the emitted `S<|@2|>`, `S<|@1|>`,
   `S<|@10|>` declarations. If it is 1, 2, 10 the order is key-sorted (and `IndexMap` insertion order is
   wrong); if 2, 1, 10 it is source order.

2. **Which instantiation-site note survives when the same instance appears in several files?**
   `Map.union` is left-biased and the union tree is built by `parallelChunksOf 4`
   (`Template.hs:88`), so the winner depends on chunk boundaries and list order, not on source
   position. *Probe:* two files each instantiating `Foo<1>` and each triggering the same error inside
   the template body; compile both orders (`kanagawa a.k b.k` vs `b.k a.k`) and compare the reported
   secondary location.

3. **Does `--frontend-passes=0` actually reach codegen, or does the C++ side reject an untyped tree?**
   `Main.hs:81-84` only checks for `ErrorF` nodes, so the raw parse tree is passed to `compile`.
   *Probe:* `kanagawa --frontend-passes=0 test/syntax/<any>.k` and observe whether it exits non-zero
   from the C++ side or crashes.

4. **Is a `DependentConstexpr` `static for` with a non-literal limit reachable in practice, and what
   does the backend do with a surviving `StaticForF`?** (`Constexpr.hs:53`.)
   *Probe:* `template<int N> inline void f() { static for (const int i : N) { int<i+1> x; } }` where
   `N` is itself a still-unresolved template parameter, compiled with
   `--template-iterations=1 --dump-program`.

5. **What is `Eq n` on `frontend`/`desugarPasses` for?** (`Frontend.hs:34,37`.) No callee in
   `Frontend.hs`, `Template.hs`, `Type.hs`, `TypeCheck.hs` or `Type/Inference.hs` appears to require it.
   *Probe:* delete the constraint and rebuild `compiler/hs` with `-Wall`; if it compiles, it is dead.

6. **Exact GHC `Show Float` output for subnormals and for values needing 9 significant digits.**
   `Mangle.hs:41` embeds it directly. *Probe:* a template `template<float F> struct S{}` instantiated
   with `1e-45`, `3.4028235e38`, `0.1`, `-0.0`, and `1.0e7`; read the mangled names out of
   `--dump-program`.

7. **Does `moveFunctions`' `parent@child` renaming ever collide with a user identifier containing `@`?**
   The lexer's identifier rule would have to be checked (`Parser/Lexer.hs`, not read for this spec).
   *Probe:* attempt to declare an identifier containing `@` and see whether the parser accepts it.
