> **A dated assessment (2026-09-22).** What was acted on is in the journal
> ("The audit, acted on — 2026-09-23") and the twin's exit (§6.4) is done
> (`docs/history/ir-elaboration.md`); the open parity work is

*2026-09-22. A read-only assessment of the Rust port of Kanagawa's frontend:
its architecture, its implementation, and the path to parity with the
Haskell reference. Written alongside active correctness work; nothing was
edited, and no build or gate was run.*

- **Baseline.** Code read at `6740eef`–`576961c`. Line numbers may drift by a
  few lines on files touched since.
- **Method.**
  - Four parallel read-only reviews: the query core, IR/types, the developer
    tools, and the backend bridge plus verification infrastructure.
  - Every headline claim was re-checked by hand. Defects marked
    **confirmed** were reproduced with the prebuilt `kg` and `kg-oracle`
    binaries on scratch files outside both trees, or read directly in the
    code.
  - Anything marked *inferred* has not been demonstrated.
- **Scope note.** CI is deliberately deferred; the project runs on local
  gates. `.github/workflows/ci.yml` is treated here as dormant, not as a
  finding.

## 1. Summary

**The discipline is exceptional.**

- Gates are honest about what they cannot decide.
- About 4,700 `File.hs:line` citations tie the code to the reference.
- Tests are proven load-bearing by mutation.
- Commits carry their before→after gate numbers.
- The parser, formatter and LSP position handling are rust-analyzer grade.

**The semantic core rests on two models joined by a text round trip.**

- Type inference runs on the lossless CST.
- Template instantiation runs on a separate IR (`kg-hir`).
- Instantiated copies are typed by printing the IR to source, reparsing it
  (the *twin*), inferring, and reading the answers back by position.

Most of the remaining cost follows from that bridge: complexity, keystroke
latency, fragility, and a self-imposed cap on the reference's fixpoint that
now blocks parity. For scale, `kg-db` + `kg-hir` + `kg-ty` + `kg-resolve` +
`kg-const` total about 76k lines including inline tests, against about 8.2k
lines of Haskell in the frontend library they port.

**Five actions with the most leverage:**

1. **Make the `Db` own every input change**, and stop bumping the world
   revision on every edit. This fixes a real staleness bug and removes
   whole-program invalidation per keystroke. Small.
2. **Lift the pass budget for batch compiles.** The reference iterates to a
   fixpoint (`template_iterations = maxBound`, `CmdArgs.hs:105`). Batch runs
   should do the same, and only the LSP should be bounded (§6.2). Small.
3. **Make parity regressions visible per program and per assertion**, not
   only as totals (§6.3). Small.
4. **Harden the language server:**
   - no mutex across queries;
   - `catch_unwind` in workers;
   - coalesced, cancellable diagnostics.

   Medium.
5. **Plan the move of inference onto the IR**, retiring the twin, as a
   staged, shadow-verified migration (§6.4). Large; this is the one item to
   schedule deliberately.

## 3. Strengths worth protecting

- **The scoreboard's honesty.**
  - The *undecidable* bucket, "fail toward silence", and the rule that
    conformance may never drop below 100%.
  - Each gate states what it cannot see (`xtask/src/ir.rs:1-60`,
    `ptdiff.rs:7-17`, `backend.rs:14-19`).
  - The guard fails any run that grows the reference tree
    (`xtask/src/guard.rs`).
- **Reference fidelity where it counts.**
  - `infer_program` matches `inferType` (`Inference.hs:26-41`), and
    `Round::apply` matches `inferExpType'` (`Type.hs:1131-1171`), clause for
    clause.
  - Where the port reinterprets, it says so in place.
- **The parser.**
  - Built rust-analyzer style: a flat event stream, markers with `precede`,
    and recovery sets.
  - Hostile-input guards: a recursion budget of 256, a step limit, and
    memoized angle scans that keep chained comparisons linear.
  - `<`/`>` stay single tokens, and composite operators are built from the
    adjacency bit the lexer records. This reproduces `notFollowedBy` exactly.
- **The IR arena.**
  - Stamped `ExpId`s that cannot be used against the wrong arena.
  - `Src` provenance on every node.
  - One rewrite substrate instead of a walker per pass.
- **The formatter.** Its verifier reparses the output and demands identical
  non-trivia tokens and comments. It refuses files with syntax errors.
- **LSP position encoding.** UTF-8 is negotiated with UTF-16/32 fallback,
  saturating and snapped to character boundaries, and tested. Capabilities
  are advertised only when answered, and a test pins that.
- **The ABI from one source.**
  - `kg-abi-gen` runs bindgen once. The loader, the `Backend` trait, the
    `Trace`/`Real` implementations and the recorder's forwarders are all
    generated from it.
  - The backend is `dlopen`ed, and `KG_BACKEND_DIR=none` gives a
    frontend-only run.
- **Engineering records.** Commit messages give reasons and numbers.
  `CLAUDE.md`'s rules ("a gate's specification is a hypothesis", "write down
  what it cannot see") were earned from real incidents.

## 4. Architecture

### 4.1 Two semantic substrates, and the twin

| Concern | Implementations today |
|---|---|
| Tree | the CST (resolve, const, ty, most kg-db passes); the IR (kg-hir lowering and rewrites) |
| Scopes | `kg_resolve::ScopeStack` (models `$quasiN`). kg-ty re-derives scopes and says `$quasiN` "is not modelled here" (`infer.rs:797-806`), so kg-db poisons duplicate keys to compensate (`passes/types.rs:655-665`) |
| `findSymbol` | `kg_resolve::find_symbol`; `SymTab::find`, "restated" (`kg-hir/src/sort.rs:20-25`) |
| Constant folding | `kg_const::ConstEval` (CST); `static_value` (IR, `rewrite/mod.rs:678-733`); an i128 folder (`kg-hir/src/width.rs:34-57`) |
| IR → `Ty` | `width.rs:62-74` and `rewrite/mod.rs:735-748`, near-duplicates |
| Demangling | `subtype.rs:944-1066` and `infer.rs:3157` |

**Why the twin exists.** Inference was written over rowan. When
instantiation produced copies that nothing could type, the choice on
2026-08-14 was between porting about 3k lines of inference onto the IR and
"print, reparse, infer, read back" (`docs/journal.md:7038`). The second was
chosen, correctly for speed at the time.

**What it costs now:**

- **Size.** `elaborate.rs` is 3.7k non-test lines, with 432 mentions of
  "twin", "synth" or `__kg_m`. The bridge also needs `rename.rs` (1.3k
  lines), `readback.rs`, a twin parser mode (`kg-syntax parse.rs:94`), and a
  side map built by walking both trees in lockstep that refuses subtrees it
  cannot pair.
- **Twin-only concepts inside the passes.** `Whole.dropped`, `copies`,
  `minted` and `twin_tree` (`undefined_symbols.rs:97-125`). `alias_leaves`
  exists because the printer writes names by their leaf only. Guards such as
  `reached_only_after_elaboration` and `dead_static_if_branches` are called
  68 times.
- **String conventions leaking into production code.**
  - `starts_with("__kg_m")` / `contains("<|")` at `pretty.rs:257`,
    `types.rs:749,862`, `conversion.rs:633` and `elaborate.rs:1697,3325`.
  - Messages are un-mangled by text search, and one real message is
    suppressed by prefix (`twin_diagnostics.rs:124, 296-322`).
  - *Inferred:* a user identifier beginning `__kg_m` would be misclassified.
- **Printer fidelity is a correctness dependency.** The sorted-IR round trip
  was 188/394 when the route was chosen (journal, same entry).
- **It now carries code generation too.** `kg-ptbridge` walks
  `RewrittenModule.ir`, with types looked up through the twin's `pairs`
  (`program.rs:79-101`).
- **Types are keyed by position.** The table key is `TypeKey{file, offset,
  end, kind, via}` (`infer.rs:366-375`), not a node ID. Its injectivity
  rests on a careful argument (`:340-365`), not on construction.

**Assessment.** The journal feared that moving inference would leave "two
engines that must agree". That duplication is already partly here: it lives
in twin-mode special cases spread across the passes rather than in one
engine. §6.4 proposes a staged exit.

### 4.2 The query layer (`kg-db`)

A hand-rolled, salsa-like design:

- inputs change through `&mut self` and bump revisions;
- queries take `&self` over `RwLock` memos;
- keys are pointer identity on `Arc`s the memo keeps alive, which is sound
  against address reuse;
- the parse is keyed on text revision, with a green-tree equality firewall
  (`db.rs:539`).

**Weaknesses:**

- **No early cutoff after the parse.**
  - `ItemTree` has no `PartialEq` (`kg-resolve/src/lower.rs:171`), and
    `ModuleTypes::same` is `Arc::ptr_eq` (`passes/types.rs:225`).
  - So a body-only edit produces a new item tree, then a new `Program`
    (`db.rs:594`), and every importer re-infers.
- **Every edit invalidates every whole-program memo.** `Db::invalidate`
  always calls `bump_world()` (`db.rs:456-460`), even for an edit to a file
  that already exists.
- **The whole-program check is quadratic and unmemoized.**
  - `diagnostics` → `elaboration` → `instances` → `check_with(roots,
    false)`, which runs the base frontend over every module, base library
    included (`db.rs:1142, 1271-1292, 1387`).
  - `frontend_diagnostics` rebuilds `Templates::of` once per module
    (`db.rs:1392`), and `visible_through_imports` likewise. That is
    O(modules²) per check.
  - This is why a keystroke costs 13× a batch `check`.
- **Per-module memos thrash across root sets.** `file_scope` compares
  `program` by pointer (`db.rs:800-803`), and `late_constants` and
  `module_instances` sit downstream. With one entry per module, two
  alternating root sets invalidate every module on every switch.
  *Inferred:* this, more than the cap of 64 root sets, explains the 2.5×
  shared-`Db` scaling noted in `CLAUDE.md`.
- **Possible order dependence** (*inferred, unproven*). `VisibleSymbols` is
  an `FxHashMap` keyed by interned `Namespace`, so iteration order follows
  interning history. `foreign_constants_with` takes the first match with
  `or_insert` over that order. It matters only when two namespaces expose
  the same stripped path. `conformance --jobs 1` exists to catch this class
  of bug.
- **A global interner mutex.** Every `resolve` locks and clones
  (`kg-base/src/interner.rs:41`); kg-db calls `resolve` 57 times and
  `intern` 123 times.
- **Oversized functions and duplication.**
  - `elaborate_module` has 16 parameters and returns a 7-tuple
    (`elaborate.rs:881`, ~490 lines).
  - `Templates::of` is built in four places.
  - "Same diagnostic" equality is written three times.
  - The checkpoint gate keys on a message prefix (`passes/mod.rs:172`).

### 4.3 The language server (`kg-lsp`)

- **One lock serializes all semantic work, taken on the main thread.**
  - `with_db` holds `dbs: Mutex<…>` for the whole query
    (`global_state.rs:249-253`).
  - `didChange` → `touch` → `invalidate_everywhere` takes the same lock on
    the main loop (`global_state.rs:213, 259-264`).
  - So a keystroke during a 1.3 s check freezes the loop. `Db` is already
    `Sync` with interior `RwLock`s, so the mutex buys nothing.
- **One panic can end the process.**
  - Workers have no `catch_unwind` (`main_loop.rs:400-407`).
  - A panic inside `with_db` poisons the mutex, and the next keystroke's
    `.lock().unwrap()` on the main thread kills the server.
  - Panic sites in non-test code: kg-hir about 87 (`expect` and
    `unreachable!`), kg-db 38, kg-resolve 17.
- **No cancellation or coalescing.**
  - `$/cancelRequest` is ignored (`main_loop.rs:304-307`).
  - Every `didChange` queues a full-program diagnostics job on an unbounded
    queue. At ~1.3 s per job, fast typing builds a backlog, and results may
    be published out of order (*inferred*).
- **Semantic diagnostics wait on elaboration.** Parse and resolve
  diagnostics could be published immediately. Any parse error suppresses
  every semantic diagnostic in the file (`db.rs:1308-1310`).
- **Feature gaps.**
  - Notes and fixes are dropped from the LSP payload
    (`handlers/diagnostics.rs:66-82`).
  - There is no code-action provider, though cast fixes already exist in
    `kg-ty/src/convert.rs:278-285`.
  - No workspace symbols and no semantic-token deltas.
  - Formatting returns one whole-file edit, which loses the cursor position.

### 4.4 The backend bridge (`kg-ptbridge`, `kg-backend-sys`)

- **No crash isolation.**
  - The C++ backend runs inside the `kg` process. The C++ side catches
    exceptions only in `InitCompiler` (`parse_tree.cpp:6283-6296`).
  - The bindings are plain `extern "C"`, so a C++ exception unwinding into
    Rust is undefined behaviour. Status reports about 43 crashes.
  - The LSP is unaffected: it does not depend on the bridge.
  - The xtask gate isolates each program in its own process but has no
    timeout.
- **A decline happens after the backend already has partial state**
  (`program.rs:73-127`). The `Trace` backend already exists, so the walk
  could run into `Trace` first and replay into `Real` only if it completes.
- **The walk is also a frontend.** `walk.rs` is 3.4k lines. It performs
  `trimExternClasses` (`:238`), post-desugar `getSymbols` (`:355`),
  `reifyEnums` (`:2760`), mangle read-back (`:434, :3226`), and string and
  format decoding (`:462-591`). It cites `Frontend.hs` 23 times against
  `ParseTree.hs` 15. `ModuleCtx` carries nine internal structures
  (`walk.rs:67-78`).
- **Every build needs `../kanagawa` and libclang.** `kg-abi-gen` asserts the
  reference headers exist (`kg-abi-gen/src/lib.rs:57`). That includes a
  build of the LSP alone.

### 4.5 Code health

- **Stale self-descriptions:**
  - `kg-hir/src/lib.rs:1-2,21` says "Wired into no pass".
  - `infer.rs:929-934` says `staticControl` "has no equivalent yet".
  - `kg-db/src/lib.rs:173` says the outer fixpoint was removed.
  - `docs/architecture.md:44` says "No rename or signature help yet".
  - `kg --help` says `build` "exits 2 — not implemented"
    (`modern/mod.rs:41`).
- **Dead code:**
  - `TyInterner` has no caller, and `TypeTable::type_of` deep-clones `Ty`
    on every read (`infer.rs:410`).
  - kg-hir's `expect-test` dev-dependency is unused.
- **Monoliths:**
  - `Algebra::infer`, 653 lines (`infer.rs:1172`; the reference's `infer`
    is about 200).
  - `xtask/src/ir.rs`, 6.9k lines: one `run` feeding about 20 unrelated
    gates.
- **Scratch paths in comments.** `~/.claude/jobs/…` appears at
  `infer.rs:1180`, `rewrite/resolve.rs:1184` and `instantiate.rs:1236`.

## 6. The pathway to parity with the reference

The current loop — take the top `ptdiff`/`backend` histogram row, reduce,
port the clause, re-gate — is working. §2 shows the pace. What follows is
about keeping that pace as the rows get harder, and removing the ceilings
the loop cannot break alone.

### 6.1 Define the finish line as a ladder

Parity is several properties, each graded by a different gate. Each rung is
blind to what the next one sees:

1. **Accept/reject:** `conformance --strict` reaches 0, including the 79
   warning assertions.
2. **Diagnostics:** `errors` reaches 0 disagreements and 0 silent, over
   *all* 834 must-reject snippets, including the 92 now skipped.
3. **The typed tree:** per-pass agreement against `kg-oracle --passes N`
   over the whole corpus (§6.3). Today `ir`'s type agreement grades 38
   roots.
4. **The ParseTree walk:** `ptdiff` *exact*, not only structural. It is 0
   today because of positions alone.
5. **Backend verdict:** `backend`, and eventually `repoint` at 72/72.
6. **Generated output:** the `.sv` both compilers emit for the same
   program. **No gate exists for this yet.**

Rung 6 is the real definition of "done" for `kg build`. Three things follow
from it:

- **Build the output gate before it is needed.** No walked program exports
  a class yet (`roadmap.md:37`), but the gate should exist, empty, so the
  first program that gets there is graded on arrival.
- **Positions are on the critical path.** The ABI passes source locations
  through to the backend (generated `Real` methods build them per call). So
  `ptdiff` exact, and plausibly byte-identical output, need span agreement.
  Span agreement is 93.4% today (divergence #25). Decide whether output
  parity means "byte-identical" or "identical modulo locations", and write
  it down. That choice decides whether divergence #25 is a gap or a
  booking.
- **Parity on the corpus is not parity on the language.** D1 was found in
  minutes and sits outside all 2,922 assertions. §6.3 proposes differential
  fuzzing for exactly this.

### 6.2 Remove the self-imposed ceilings first

These are divergences the port introduced, not clauses it has yet to port.
Each one caps what row-by-row porting can reach.

**1. The pass budget.**

- The reference's instantiation loop is unbounded by default:
  `template_iterations = maxBound` (`CmdArgs.hs:105`), looping in
  `instantiateTemplates` until no instance is decided (`Template.hs:50-62`).
- kgrust caps it at `MAX_PROGRAM_PASSES = 4` × `MAX_ROUNDS = 8`
  (`elaborate.rs:629, 1800`), and the cap was chosen **for keystroke
  latency**.
- The latest journal entry (`1c56409`) shows it now binds. The `unit::test`
  chain (46 programs) needs a fifth pass. Six passes move `auto_inline.k`'s
  first divergence from call #521 to #3259, but cost 1384 → 2038 ms per
  keystroke, so the budget stayed at 4.
- **Recommendation:** make the budget a parameter.
  - Batch entry points (`kg build`, `kg check`, the compat `kanagawa`, and
    every gate) iterate to the fixpoint, as the reference does.
  - The LSP keeps a bound, or better, runs unbounded but cancellable.
  - Report hitting the bound as a diagnostic-level event, never silently.
  - This separates correctness from interactivity, which
    `CLAUDE.md`'s correctness-first rule already implies.

**2. Per-module inference with frozen imports.**

- The reference infers the whole program in one fixpoint (`inferType` over
  the program list).
- kgrust infers per file with imports frozen (`passes/types.rs:98`). It
  then recovers cross-module facts through "program passes" that hand
  foreign decisions to their owners, which is the loop the budget cuts.
- The recurring blocker the roadmap names is a symptom of this. The base
  inference types an alias to an instance of an imported template as
  `Unresolved`, so the whole `unit::assert_equal` call site in
  `auto_inline.k` is untyped and nothing deduces.
- Until §6.4, make this seam explicit: a per-program fixpoint over module
  inference results, memoized per module (§4.2), so that extra passes cost
  a re-check of the modules that changed rather than every target module.
  The journal names that same lever: "phase 2 re-elaborates every target
  module on every pass".

**3. Printer fidelity.** While the twin exists, every construct the printer
cannot spell becomes a decline, a special case, or a lost fact:

- a hoisted lambda's capture type;
- `$x0`;
- frames;
- dropped qualifiers.

Track the sorted-IR round trip (`xtask ir`) as a ratcheted number, since
§4.1 relies on it.

### 6.3 Instruments that make each row cheaper

**Per-program and per-assertion ratchets, not totals.**

- `891fc8c` moved `ptdiff` 1735 → 1742 as "9 up, 2 down". A total that
  rises can hide a program that regressed.
- Store the passing *set* for `conformance --strict`, `errors`, `ptdiff`,
  `backend` and `repoint` in a checked-in baseline file.
- Have each gate print "newly passing / newly failing" against it, and fail
  on any newly failing entry unless the baseline is updated in the same
  commit.
- This is cheap, and it turns every gate run into a regression test.

**A per-pass differential, to localize divergences by cause.**

- `ptdiff`'s first divergent call is often far downstream of the cause. A
  missing `Closure` copy surfaces at call #521.
- `kg-oracle --tree --passes N` already exists. Normalize both trees
  (synthesized names by adjacency, positions dropped or mapped) and report,
  per program, the **first pass at which we diverge**.
- A histogram by first divergent pass is a work list ordered by pipeline
  position, and an upstream fix often clears many downstream rows.
- `xtask ir` has most of the machinery. It needs to cover every pass and
  the whole corpus, not 38 roots.

**Automated reduction.**

- The journal's most valuable entries are hand reductions ("nine
  library-free lines").
- Add `xtask reduce <program>`: a delta-debugging reducer over `.k` source
  whose interestingness test is "`kg` and `kg-oracle` still disagree the
  same way". Use the same first-divergence signature as `ptdiff`/`errors`.
- Reduced cases double as unit tests.

**Differential fuzzing against the oracle.**

- `xtask fuzz` today checks only that `check_source` does not crash
  (`xtask/src/fuzz.rs:206-213`).
- Add a mode that mutates corpus programs — swap operators, insert unary
  minus or parentheses, reorder declarations, rename to collide — and
  compares accept/reject and the first error against `kg-oracle --errors`.
- D1 is exactly the class this finds. It also extends the "must not
  diagnose earlier than the reference" guarantee beyond the corpus.

**Widen what is graded, cheaply:**

- **The 92 skipped `errors` snippets.** Teach the oracle driver `--define`,
  `--using`, `--target-device` and `--Werror` (`gaps.md` §C calls this
  cheap).
- **The 79 warning assertions.** Booked to "the semantic passes", but the
  shadow, conversion and initializer-override warnings now exist. Survey
  which are decidable (`gaps.md` §D suggests the same), since the strict
  log already shows `initializer-overrides` failures.
- **The 241 backend-code assertions.** `conformance` still books them
  undecidable, although `backend` now grades them end to end. Fold the
  backend verdict into `conformance` behind a flag, so the headline covers
  all 2,922 assertions in one number.

**Declines as a first-class histogram.** About 510 declined walks are the
largest `backend` bucket. Keep each decline reason's count in the baseline
file, so a change that converts a decline into a disagreement is visible as
such.

### 6.4 The structural convergence: one IR, one fixpoint

The families `gaps.md` calls "Large, architectural" are downstream of §4.1.
These are A1 (instances inside copies, cross-module rounds) and A2 (closure
typing, the `Closure` copies at the top of `ptdiff`). They are being closed
one mechanism at a time, each fix adding a twin-specific concept. Moving
inference onto `kg-hir` retires the category.

A staged path that keeps every gate green:

1. **Contain (small, now).**
   - One `is_mangled` / `is_alias` predicate owned by kg-hir replaces every
     string test.
   - kg-ty consumes `kg_resolve::ScopeStack` instead of re-deriving scopes.
   - One IR constant folder, one IR → `Ty` helper, one closure-path
     constant.
2. **Abstract (medium).**
   - Put `Round`/`Algebra` behind a node-view trait implemented by both the
     CST and the IR, with a type table keyed by an abstract node ID rather
     than `TypeKey` offsets.
   - The CST implementation is today's behaviour, so gates must be
     byte-identical after this step.
3. **Shadow (medium).**
   - Run IR inference alongside the twin in elaboration, and diff the two
     type tables per node in `xtask ir`.
   - The twin remains the source of truth. The diff count is the migration
     gate, and it must reach zero on the corpus.
4. **Switch (medium).**
   - Elaboration takes types from IR inference.
   - Delete `rename.rs`, `readback.rs`, the twin parser mode, the side maps
     and `twin_diagnostics`' un-mangling.
   - Diagnostics inside copies map home through `Src` provenance, which the
     arena already carries.
5. **Converge the loop (large).**
   - Replace per-module twins and program passes with one whole-program
     instantiation loop over a single arena, mirroring
     `instantiateTemplates` (`Template.hs:50-62`) and `inferType`'s
     whole-program fixpoint.
   - The budget question disappears; the LSP is bounded by cancellation.
6. **Keep the CST engine for the IDE.** Hover, completion and inlay hints
   on unsaved, erroneous buffers still want a CST-level fast path. After
   step 4 it is an IDE layer, not a compiler stage.

Steps 1–2 are safe to do alongside the current row-by-row work. Steps 3–5
are best started once the strict count levels off, when the remaining rows
are mostly A1/A2. The step-3 diff will say when that is.

## 7. The local verification loop

CI is deferred, so `scripts/gates.sh` and the xtask gates are the only
enforcement. Today they report, but they do not enforce:

- **`gates.sh` cannot fail.**
  - It has no `set -e`/`pipefail`, and every stage is piped through
    `grep`.
  - Clippy runs without `-D warnings`.
  - `ptdiff`, `backend` and `repoint` are not run.
  - "Strict must never rise" is enforced by a human reading a log.
- **The ratchets live nowhere local.** The only encoded thresholds are
  literals in the dormant `ci.yml`, and those are stale (strict 116,
  repoint 57).
- **Recommendation:**
  - One checked-in baseline file: totals *and* the per-program sets from
    §6.3.
  - Read by the xtask gates and by `gates.sh`.
  - `gates.sh` exits non-zero on any regression and prints a one-screen
    summary.
  - When CI returns, it reads the same file.
- **Record which binary each gate grades.** `backend` spawns
  `target/release/kanagawa` unchecked (D8), and memory notes already warn
  to rebuild first. Have xtask build it, or check a stamp.
- **Portability.** `oracle/build.sh:15` defaults to `a home directory`,
  and there is no cabal freeze file. Fine for one machine; worth a freeze
  file before a second contributor.

## 8. Developer-facing layers

- **Parser.**
  - D1 aside, the main gap is incrementality. There is no incremental
    reparse; the LSP reparses the whole file per revision
    (`global_state.rs:317-327`).
  - `skip_balanced` scans to end of file on an unclosed `(`/`[`, and
    `at_decl` calls it at each statement start. Possibly quadratic on broken
    input; *unmeasured*.
  - Parser state lives in thread-locals (`lookahead.rs:147`), which is safe
    only because `source_file` is the sole entry point.
- **Diagnostics.**
  - The model has severity, labels, notes and fixes, but a single `Code`:
    every frontend error is `Error 1`, so `kg explain 1` covers everything.
  - `with_note` is never called outside kg-diag.
  - The renderer marks labels with a single `-`, counts carets in bytes,
    shows only the first line of multi-line spans, and prints a fix as a
    message without the edit.
  - Recommendation: internal sub-codes (for example `E1xxx`), with the
    legacy output still printing `Error 1`; a real renderer (ariadne or
    annotate-snippets); and code actions from the existing fixes.
- **Formatter.**
  - With `sort_imports` on, verification weakens to comparing token
    multisets (`verify.rs:91-97`), though import order changes meaning.
  - A verification failure becomes "no edits" silently (`kg-lsp fmt.rs:67`).
    Formatter bugs should be loud.
- **CLI.**
  - Stale `build` help text (§4.5).
  - `kg check` prints diagnostics to stdout, not stderr.
  - The compat flag table, every row cited to `CmdArgs.hs`, is a model to
    keep.
- **Editors.**
  - The VS Code client selects only the `file` scheme (`extension.ts:79`),
    so untitled buffers get nothing although the server supports them.
  - No packaging and no tests.
  - No configs for other editors.

## 9. Documentation

The documents carry real knowledge. The problem is retrieval.

- **`status.md` is 74 KB.**
  - Single table cells run over 4,000 characters of "N before X" history.
  - It says "none is hand-maintained", but the numbers are pasted.
  - It contradicts itself: "2296/2296 … 309" at `:55-56` against its own
    headline, and a section titled "Where the 309 strict failures live".
  - The `ptrace` row still reads "not a gate yet … until the bridge's
    step 3".
- **The docs disagree with each other.** `roadmap.md`, `gaps.md` and
  `status.md` give different ptdiff, backend and strict figures on the same
  day.
- **`journal.md` is 11.5k lines (690 KB)** with 141 sections, most undated
  and unindexed. It claims "newest first" but is not.

**Recommendation:**

- Have the gates write a `status.json`, and render `status.md`'s headline
  from it. History belongs in git and the journal.
- Give the journal a dated index of the decisions that still bind: the
  twin, the pass budget, the divergence bookings.
- Keep `gaps.md` as the one working list, re-measured rather than edited.
