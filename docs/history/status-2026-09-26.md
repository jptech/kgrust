What works, what is partial, what has not been started. The headline is
rendered from the gates, never typed:

```
scripts/gates.sh > gates.log 2>&1    # every gate; red on any regression
cargo xtask status-md                # the headline below, from that run
```

`scripts/quick.sh <test filter>` is the half-minute inner loop. Every
corpus-walking gate is spread over threads that each own a `Db`;
`conformance --jobs 1` is the one-`Db` loop in corpus order. See
[`journal.md`](../journal.md), "The gates, spread over threads" and "The
testing loop, measured". The prose sections further down are older than the
headline and are dated where they quote a number.

## Works

- **Lexer, parser, CST.** Lossless rowan tree, generated typed AST, event-stream
  parser decoupled from the tree. Fuzzed.
- **Formatter** (`kg-fmt`). Comment-preserving, with a verifier that refuses any
  edit that would change the program. Reachable from `kg fmt` *and* from the
  language server.
- **Query layer** (`kg-db`). Salsa-shaped, memoized on identity, whole-program,
  bounded memos. Two revisions: per-file text, plus a `world` revision for file
  existence.
- **Language server.** Diagnostics from the real frontend — a `while
  compiling` frame published as related information, so an error in a
  template body links to the instantiation that compiled it — formatting,
  goto-definition, hover, find-references, rename (with `prepareRename`),
  signature help, completion, inlay hints, document highlight, symbols,
  folding, selection ranges, semantic tokens.
- **CLI.** `kg check` / `fmt` / `lsp`, plus a legacy-compat binary that takes the
  reference's own flags so upstream's runner can grade us.

**Performance.** Keystroke is 110.5 ms against a 16 ms frame, **up** from
96.9 → 102.3 → 104.2. (Absolute worst-case numbers drift a few percent between
runs with machine load; the step sizes below come from interleaved A/Bs, which
do not.) `templateTypeCheck` accounts for the last step: an
interleaved A/B over four pairs gives `check` 67.2→68.7 ms and a keystroke
102.3→104.2 ms, distributions not overlapping. That is a second `descendants()`
walk of the edited file, and it buys 14 assertions. Before that, memoizing the type table per module removed a rebuild from every *batch*
check — `xtask conformance` end to end went 14.1 s to 12.3 s — but a keystroke
invalidates the memo by definition, and the passes downstream now have resolved
types where they used to see `Ty::Undefined` and bail. That extra work is the
feature; it is a cost, not a saving.

The number read 70.6 ms until the keystroke stage was found to be feeding each
file its own bytes back: `parse_module` keeps the old `Arc<Parse>` when a reparse
compares equal, and `item_tree` and `type_table` are keyed on that `Arc`'s
identity, so nothing below the parser was invalidated. The stage now appends a
trailing space, and `re_entering_identical_text_leaves_the_type_table_memoized`
pins the fact it depends on.

The formatter is the slowest stage in the toolchain — 97.1 ms worst case,
against 74.6 ms for a full check — and has now been profiled. A quarter of it
was parsing, because formatting one file parsed it four times: once at the top,
once in each of `realign`'s two anchor passes, and once in the verifier.
`realign`'s second parse is now taken only when the first pass actually moved
something, which is worth about 4.5%. The rest is structural — lowering 27%,
verification 21% — and the profile is the argument for leaving it alone. The
lever that would move it is a faster parser, which appears four times here and
would pay off in `check` and `keystroke` too. See [`journal.md`](../journal.md).

## How the materialised tree gets a type — the route, decided

Pass 8 is a fixpoint: materialise the instances this round decided, infer over
the *result*, and go again — 53% of the 351 oracle-readable roots need two or
more rounds and one needs **twelve**. Materialisation is ported. Inference over
what it produces is not, and there were two ways to get it:

**(a) port `inferExpTree` onto the IR** — a second inference engine beside
`kg-ty`'s, which would also have to re-target `kg-const`'s fold from `ast::Expr`
to the arena. **(b) print the materialised subtree, reparse it, and let the
existing frontend infer it.** Route (b) is chosen and the decision is written up
in [`journal.md`](../journal.md) with its two costs priced: no mangled or
synthesized name lexes (`<|` never lexes at any length; `$this` and `?lambda0`
fail as identifiers), so a **rename layer** is mandatory; and the printed copy
needs a **read-back** that lands the inferred types on the arena nodes they came
from.

What has landed for it:

- **`sorted trip: 403/403`.** The round trip over `lower_sorted` — the tree the
  oracle differential grades and the one the rewrites run on. It read
  **188/394** when the route was chosen, and closing it meant exact qualifier
  printing rather than a heuristic. A print-and-reparse route rests on the
  printer being *exact*, so this is the route's foundation gate, not a nicety.
- **`pretty_with_source`**, guarded by `ModuleIr::lowered_len` rather than by
  `Src::written == Own`. `Own` is neither "synthesized" nor "rewritten" — it
  means *sole claimant of a `(range, kind)` in its tree* — and an `Own`-guarded
  slice would have printed the original spelling back over a rewritten name,
  silently un-rewriting it. A fresh arena index is the only reliable "a rewrite
  made this", and it bounds the whole subtree.
- **`kg_hir::rename`**, the bijective `__kg_mN` layer, with the reverse
  substitution over `Ty` that the read-back needs. Graded by `rename:
  351/351` above. What it *refuses* is the load-bearing half — a rename
  freshens every ancestor past `lowered_len`, so renaming a name the printer
  never emits costs the printer its source slices for a whole subtree and
  changes nothing the parser sees.
- **The census fold** (`kg_db::fold`), which was scheduled regardless of
  route: `evaluateConstexpr`'s half of `inferExpTree` asked rather than
  rewritten, so `W<8>` and `W<bitsizeof(uint8)>` are one instance. +2
  assertions, and 28 templates / 53 distinct instances against 26 / 49.

- **The read-back** (`kg_hir::readback`), writing five-field `TypeKey`s, and
  **the diagnostics half** (`kg_db::elaborate::twin_diagnostics`, 2026-09-07):
  the passes run over the twin and a diagnostic inside a copy walks the same
  side map home — `Src::head` is where it is reported, `Src::via` is the
  `while compiling` chain. Both directions of the map are now load-bearing,
  which is the argument for keeping it exact rather than approximate.

Outstanding: the cross-module shapes the route declines — depth-two
instances, foreign deduced calls with value arguments, an exported helper
instance — and `undefinedSymbols` over a copy; roadmap item 14.
