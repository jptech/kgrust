## Reading them

- The backend's `Middle-end (inclusive)` timer encloses all of its work,
  output included (`kanagawa.cpp:54-202`); a run's frontend is its wall
  time less that figure. Stages nest and some add up across the backend's
  threads, so they do not sum to its wall time.
- `cache.k`'s whole build is noisy on both sides: `RemoveUnusedGlobals`
  and `RemoveDeadOperations` swing between runs. Three repeated runs each
  side (not saved as files; `kanagawa --verbose`, same arguments): ours
  9.72 / 9.74 / 8.78 s wall, `RemoveUnusedGlobals` 4.81 / 4.78 / 3.70 s,
  `RemoveDeadOperations` 2.43 / 2.51 / 1.84 s; the reference's 9.50 /
  11.46 / 11.48 s, 3.40 / 4.80 / 4.77 s, 1.80 / 2.40 / 2.40 s.
- MiB is `/usr/bin/time -l`'s bytes / 2^20. On macOS the peak footprint is
  the figure `cargo xtask mem` budgets; the resident set is what the
  comparison tables print, the reference's footprint being near its RSS.
